## 1. Goal / scope

- A `fill_form` page for signup, promote, and login flows, including the page that signup_login shows after it continues into signup.
- Form fields under the login ID input on the signup and promote identify page.
- Constraint errors and hook `invalid_form_field` messages shown under their fields. The hook `title` and `reason`, and messages whose key matches no field, are shown above the form.
- `fill_in_user_profile` keeps its `panic` in the navigator. It is deprecated and untouched.

## 3. Shared form helpers

New file `pkg/auth/handler/webapp/authflowv2/form.go`:

```go
// FormFieldsInput is the `fields` input built from the posted HTML form,
// plus the key of each item so error locations /fields/{i}/value map back to fields.
type FormFieldsInput struct {
	Fields []map[string]any
	Keys   []string
}

func BuildFormFieldsInput(form url.Values, data declarative.FillFormDataForm) FormFieldsInput
```

`Fields` is always a non-nil slice (`[]map[string]any{}`). A nil slice would marshal to `"fields": null` in `feedInput` (`authflow_controller.go:900`) and fail the `type: array` schema, so an all-optional page could not be submitted empty (UC3).

HTML input names are the field keys, which are JSON pointers, as on the settings page. `/address` uses `/address/<sub>` per sub-field. Fields are processed in `data.Fields` order. Per `type`, the field is handled as follows:

| type | Read | Sent as | Skipped when |
|---|---|---|---|
| `string`, `email`, `url`, `phone_number`, `enum`, `country_code`, `timezone`, `date` | `form.Get(key)` | string | empty |
| `integer` | `strconv.ParseInt` | int64. On a parse error the raw string is sent, so the server returns the type error. | empty |
| `number` | `strconv.ParseFloat` | float64. On a parse error the raw string is sent. | empty |
| `boolean` | `form.Get(key)`. A checkbox `value="true"` comes before a hidden `value="false"`, so the first value wins. | bool | never |
| `address` | each of `formatted`, `street_address`, `locality`, `region`, `postal_code`, `country` from `form.Get(key+"/"+sub)` | object of the non-empty sub-values | all empty |

```go
// FormErrorLocations maps each submitted field key to the cause locations of that field:
// "/fields/{i}/value", plus "/fields/{i}/value/<sub>" for each address sub-key.
func FormErrorLocations(data declarative.FillFormDataForm, keys []string) map[string][]string

// HookFieldMessages extracts invalid_form_field messages from a HookDisallowed APIError.
// unmatched holds messages whose key is not in keys.
func HookFieldMessages(apiErr *apierrors.APIError, keys []string) (byKey map[string]string, unmatched []string)
```

`HookFieldMessages` reads `info.reasons[*].reasons[*]` where `type == "invalid_form_field"`. The error reaches the page through `ErrorState`, which is JSON in Redis (`error_service.go:24-28, 88-95`). So `info.reasons` arrives as `[]any` of `map[string]any`, never as `[]hook.OperationDisallowedItem`, and the function type-asserts maps. Tests build their input errors through a JSON round trip.

`pkg/auth/handler/webapp/viewmodels/base.go`: `SetFormJSON` also stores `m.RestoredForm = form`, through a new field `RestoredForm url.Values \`json:"-"\``. After the redirect that follows an error, `BuildFormFieldsInput(RestoredForm, …)` recomputes the same `Keys` the failed POST used. So error locations map back to fields without extra state.

New file `pkg/auth/handler/webapp/authflowv2/viewmodels/form.go`:

```go
type FormFieldViewModel struct {
	Key           string
	Type          string
	Label         string
	LabelHTML     htmltemplate.HTML // boolean only: label already sanitized by the Authflow API
	Required      bool
	Value         any               // restored form value if present, else the field's current value
	Options       []declarative.FillFormDataFieldOption
	Suggestions   []string
	Constraints   *declarative.FillFormDataFieldConstraints
	Error           *apierrors.APIError // causes of this field only; nil when none
	MissingRequired bool                // required, not submitted, and the input failed
	HookMessage     string
}

type FormViewModel struct {
	Name                  string
	Fields                []FormFieldViewModel
	UnknownError          *apierrors.APIError // any error not attributed to a field
	HookUnmatchedMessages []string
	// Data the input partials read from the root context.
	Timezones []tzutil.Timezone // for __timezone_input.html, as in settings_profile.go:258
	Alpha2    []string          // for __country_input.html, as in settings_profile.go:259
}

func NewFormViewModel(form declarative.FillFormDataForm, base *viewmodels.BaseViewModel) FormViewModel
```

`NewFormViewModel` does the following:

1. Compute `keys` with `BuildFormFieldsInput(base.RestoredForm, form).Keys`.
2. When `base.RawError != nil`, call `template.ResolveError(base.RawError, input)` once in Go (`pkg/util/template/funcerror.go:51`). `input` has one entry per submitted key, `{key: {"by_location": FormErrorLocations(form, keys)[key]}}`. Then:
   - Each field's `Error` is the entry for its key.
   - `UnknownError` is the `unknown` entry, minus `ValidationFailed` causes at location `/fields`.
3. The required-field check fails at `/fields` (Part 2 uses `contains`), not under a field. So when the error is `ValidationFailed` with a cause at `/fields`, set `MissingRequired` on every required field whose key is not in `keys`. This is the only feedback for required select, timezone, and country inputs, which are hidden `<input class="hidden">` elements (`__select_input.html:20-26`), and for `address`. The signup form is also `novalidate` (`signup.html:138`).
4. When `base.RawError` reason is `HookDisallowed`, set `HookMessage` and `HookUnmatchedMessages` with `HookFieldMessages`.
5. Fill `Timezones` and `Alpha2` the way `settings_profile.go:258-259` does.

`LabelHTML` is `htmltemplate.HTML(label)` for `boolean`. This is safe because Part 2 sanitized the label with `htmlutil.SanitizeLinksHTML` before it entered the API data.

New partial `resources/authgear/templates/en/web/authflowv2/__form_fields.html`. It is called as `template "authflowv2/__form_fields.html" (merge (dict "Form" $.Form) $)`, so the partial sees the root context that `__error.html` needs (`$.Translations`, `$.SliceContains`, `.PasswordPolicies`, `__error.html:42-44`). For each field, it renders:

- The label, with a required marker using `v2.component.form-field.required-marker`.
- The input, chosen by type:
  - text, email, and URL use raw `<input class="input">`, with `type` set accordingly.
  - `phone_number` uses `__phone_input.html`.
  - `enum` uses `__select_input.html` with `Options`.
  - `country_code` uses `__country_input.html`.
  - `timezone` uses `__timezone_input.html`.
  - `date` uses `__date_input.html`.
  - `string` with `suggestions` uses an `<input list>` with a `<datalist>`.
  - `boolean` uses the `.checkbox` markup of `__device_token_checkbox.html` (input, icon label, text label) with `value="true"`, followed by a hidden `false` input with the same name. The text label is `LabelHTML`.
  - `address` uses six text inputs labelled with the existing `v2.page.settings-profile-edit-address.default.*` keys.
- The HTML `required` attribute only on visible native inputs: text, email, url, date, and checkbox. Hidden inputs used by the select, timezone, and country components never get it, and `address` is checked by the server. Server-side `MissingRequired` covers the rest.
- `__string_constraints_hint.html` when `Constraints` is set.
- Under the input:
  - `HookMessage`, if any.
  - Else, if `MissingRequired`, `v2.component.form-field.required-error`.
  - Else, if `.Error`, `include "authflowv2/__error.html" (merge (dict "Error" .Error "PatternPointer" .Key) $)`. `PatternPointer` makes the `pattern` branch from Part 1 pick `custom-attribute-pattern-error-{key}` or `standard-attribute-pattern-error-{key}`, because the cause location is `/fields/{i}/value`.

The partial is registered in `pkg/lib/web/html.go` and `BaseComponentsHTML`.

For signup_login, the identify options have no `form`, so `FormsByIdentification` is empty and the page is unchanged. The fields appear on the `fill_form` page instead (section 4).

`authui/src/form.ts` restores the form from `data-restore-form-json-value`. Because the inputs are named by key, entered values survive an error, which covers spec UC2 ("keeps what they entered in the other fields").

`RestoreFormController.connect` (`authui/src/form.ts:187-198`) currently sets `elem.value` on every input with a matching name, and `SetFormJSON` keeps only `form.Get(key)`. That corrupts the boolean checkbox and its hidden `false` input after any error:

- A checked box makes both values `"true"`, so unchecking still posts `true`.
- An unchecked box gets value `"false"`, so checking it posts `false`.

Change the loop as follows:

- For `type=checkbox` and `type=radio`, set `elem.checked = (value === elem.value)` and never change `elem.value`.
- Skip a `type=hidden` input when the same form has a checkbox with the same `name`.

The only existing checkbox is `x_device_token` (`__device_token_checkbox.html`), and it has no hidden twin. After this change it gets its checked state restored after an error, instead of losing it.
