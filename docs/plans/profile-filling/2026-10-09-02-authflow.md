## 1. Goal / scope

- New step type `fill_form` in `signup_flows`, `promote_flows`, and `login_flows`, including nested branch steps.
- New `form` key on `identify` branches of signup and promote flows, for `email`, `phone`, and `username` branches.
- Config validation for forms.
- `fill_form_data` action data, with fields, labels, current values, and constraints.
- Submitted attributes are written in the flow's run effects. They are committed only when the flow finishes.
- New blocking event `authentication.form.post_submitted`. Its `invalid_form_field` reasons surface in `HookDisallowed`.
- `user.profile.pre_update` and `user.profile.updated` fire once when a login or promote flow finishes, if a form was submitted.
- When signup_login continues into signup, the identify branch's form is shown as its own `fill_form` action.
- The existing `fill_in_user_profile` step is marked deprecated in code only. Its behavior is unchanged.

Out of scope:

- forms in generated flows
- the portal hook-event picker. `authentication.form.post_submitted` is configured in YAML.

### 2.3 Validation in Go

New function in `authentication_flow_form.go`. It is called directly from `AppConfig.Validate` (`pkg/lib/config/config.go`), next to `c.validateAuthenticationFlow(ctx)`. It must not go inside `validateAuthenticationFlow`, which returns early when `ui.authentication_flow` is unset (`config.go:367`), so most projects would skip the checks:

```go
func validateAuthenticationFlowForms(ctx *validation.Context, c *AppConfig)
```

Call flow:

1. For each `i, f` in `c.AuthenticationFlow.SignupFlows`, `PromoteFlows`, and `LoginFlows`, call `validateFormsInSteps(ctx.Child("authentication_flow", "<flows key>", strconv.Itoa(i), "steps"), c.UserProfile, f.GetSteps(), false)`.
2. `validateFormsInSteps(ctx *validation.Context, up *UserProfileConfig, steps []AuthenticationFlowObject, identified bool) bool` loops over the steps with index `k`. It returns whether the user is identified after the last step. For each step:
   - When the step type is `identify`, for each branch `j`:
     - if the branch has a form, call `validateForm(ctx.Child(k,"one_of",j,"form"), up, form)`.
     - recurse into the branch's steps with `identified=true`.
     - After the step, set `identified = true`.
   - When the step type is `fill_form`:
     - if `!identified`, emit `EmitErrorMessage("fill_form must come after an identify step")` at `ctx.Child(k)`.
     - Call `validateForm(ctx.Child(k,"form"), up, step.GetForm())`.
   - For any other step with `GetOneOf()`, recurse into each branch's steps with the current `identified`. Branch results are ignored, because only `identify` changes the state.
3. `validateForm(ctx, up, form)`, for each field `n`:
   - If `!isFillableUserProfilePointer(up, pointer)`, emit `EmitErrorMessage("attribute is not fillable")` at `fields/n/user_profile/pointer`.
   - If the pointer is already in a local `seen` set, emit `EmitErrorMessage("duplicated pointer")` at the same location.
4. `isFillableUserProfilePointer(up *UserProfileConfig, pointer string) bool`:
   - Return false for `/email`, `/phone_number`, `/preferred_username`, and any `/address/` prefix.
   - Standard attribute: true iff `up.StandardAttributes.GetAccessControl()[accesscontrol.Subject(pointer)][RoleEndUser] == AccessControlLevelReadwrite`. `AccessControlLevelReadwrite` is defined in `pkg/lib/config/user_profile.go`.
   - Custom attribute: find it by `Pointer`. True iff `AccessControl.EndUser == AccessControlLevelStringReadwrite`.
   - Unknown pointer: false.

The fillable rule checks the current access control on every load and save, so it also covers the spec's rule that an access-control change making an attribute non-fillable is rejected. Only new keys are validated, so existing configs are not affected.

New file `pkg/lib/authenticationflow/declarative/form.go`. It holds the shared, non-node helpers:

```go
// FormFieldInput is one item of the `fields` input. It is persisted in flow state.
type FormFieldInput struct {
	Key   string `json:"key"`
	Value any    `json:"value"`
}

func formFieldKey(f *config.AuthenticationFlowFormField) string // user_profile → Pointer

// buildFormFieldsSchema builds the schema of the `fields` array for form.
func buildFormFieldsSchema(cfg *config.AppConfig, form *config.AuthenticationFlowForm) validation.SchemaBuilder

// validateFormFields checks what JSON Schema cannot: duplicate keys and string constraints.
func validateFormFields(vctx *validation.Context, cfg *config.AppConfig, form *config.AuthenticationFlowForm, fields []FormFieldInput)

// formFieldsToAttrs returns one attrs.T per form field, in form order. A field absent from input gets nil, so its value is cleared.
func formFieldsToAttrs(cfg *config.AppConfig, form *config.AuthenticationFlowForm, fields []FormFieldInput) (std attrs.List, custom attrs.List)

// formFromFlowObject panics if o is not an AuthenticationFlowObjectFormProvider with a non-nil form.
func formFromFlowObject(o config.AuthenticationFlowObject) *config.AuthenticationFlowForm
```

`buildFormFieldsSchema`:

- `fields`: array; items are objects with `additionalProperties: false`, `required: [key, value]`.
- `key`: an `enum` of every field key.
- `items.allOf`: one `if {key const K} then {value: S(K)}` per field.
- `S(K)` is the value schema:
  - Standard attributes: `stdattrs.SchemaBuilderForPointerString(K)`, except that `/locale` gets an extra `Enum(cfg.Localization.SupportedLanguages...)`.
  - Custom attributes: `cfg.UserProfile.CustomAttributes` entry `.ToSchemaBuilder()`.
- `fields.allOf`: one `contains { key const K, value: F(K) }` per required field. `F(K)` means "filled":
  - for a boolean: `const true`
  - for `/address`: `S(K).Clone()` plus `AdditionalPropertiesFalse()` and `AnyOf` of `required: [sub]` for each of the six sub-keys. Every sub-key already has `minLength: 1`, so at least one sub-attribute is non-empty. The address schema itself has no `additionalProperties: false` (`authn/stdattrs/validate.go:12-20`), so `MinProperties(1)` would accept `{"foo": "x"}`. New method `func (b SchemaBuilder) AnyOf(builders ...SchemaBuilder) SchemaBuilder` in `pkg/util/validation/schema_builder.go`. `Clone()` keeps the shared builder unchanged.
  - otherwise: `S(K)`. It already has `minLength: 1` for strings, and numbers cannot be empty.

`validateFormFields`:

- A second occurrence of a key emits `EmitErrorMessage("duplicated key")` at `/fields/{i}/key`.
- Each value that is a non-empty string and has constraints calls `attrs.ValidateStringConstraints(vctx.Child("fields", i, "value"), cons, s, multiline)`. Constraints come from `cfg.UserProfile.StandardAttributes.GetStringConstraints(K)` or the custom attribute's `StringConstraints()`.
- For `/address`, each sub-key with an entry `/address/<sub>` is checked at `/fields/{i}/value/<sub>`.
- Every submitted value is checked, whether or not it changed. This is the spec's rule that current values are re-checked on submission.

`NewFillFormDataForm` call flow, per field, in form order:

1. `fillFormFieldType(cfg, pointer) FillFormFieldType`. This is the type table in [user_profile field](../../specs/user-profile/profile-filling.md#user_profile-field). `/gender` also sets `Suggestions: ["male","female"]`.
2. `formFieldLabel(ctx, deps, pointer, isCustom) (string, error)`:
   - The key is `custom-attribute-label-{pointer}` or `standard-attribute-label-{pointer}`.
   - If `deps.Translations.HasKey`, call `RenderText(key, nil)`. Otherwise use `labelutil.Label(firstToken)`.
   - For a custom `boolean`, the result goes through `string(htmlutil.SanitizeLinksHTML(label))` (Part 1).
3. Options:
   - `enum`: for each value, the label key is `custom-attribute-enum-label-{pointer}-{value}`, falling back to `labelutil.Label(value)`, as the settings page does (`viewmodels/settings_profile.go:223`).
   - `/locale`: for each `cfg.Localization.SupportedLanguages`, the label key is `language-{tag}`, the key `__locale_input.html` uses.
4. Value: read from `user.StandardAttributes[name]` or `user.CustomAttributes[name]`. Absent becomes nil.
5. Constraints:
   - from Part 1 `StringConstraints`. `PatternMessage` is rendered from `custom-attribute-pattern-error-{pointer}` or `standard-attribute-pattern-error-{pointer}` when the key exists.
   - from custom `Minimum` and `Maximum`.

The user comes from `deps.Users.Get(ctx, userID, config.RoleEndUser)`. It is read inside the request's read-only transaction, where run effects have already been applied. So values populated by an earlier identify step, or submitted in an earlier form, are visible.

## 4. Runtime flow

### 4.1 `fill_form` step

New file `input_fill_form.go`:

```go
type InputSchemaFillForm struct {
	JSONPointer    jsonpointer.T
	FlowRootObject config.AuthenticationFlowObject
	Config         *config.AppConfig
	Form           *config.AuthenticationFlowForm
}
// GetJSONPointer, GetFlowRootObject, SchemaBuilder, MakeInput, FlowActionType

type InputFillForm struct {
	Fields []FormFieldInput `json:"fields"`
}
func (*InputFillForm) Input()
func (i *InputFillForm) GetFormFields() []FormFieldInput
```

`SchemaBuilder()` is `object, additionalProperties: false, required [fields], properties { fields: buildFormFieldsSchema(...) }`. `additionalProperties: false` stops an identify input from parsing as a form input.

`MakeInput(ctx, raw)`:

1. Parse with the schema.
2. `vctx := &validation.Context{}`, then `validateFormFields(vctx, …)`.
3. If `vctx.Error("invalid form")` is non-nil, return it. It is a `ValidationFailed` with causes at `/fields/{i}/value`.

Every form error is reported before the flow reacts, so the flow stays in the step.

**One raw input feeds at most one form.** Within one request, `Accept` offers the same raw input to every input reactor it reaches (`accept.go` `Accept`). `feedInput` also re-runs `Accept` with the same input after `ErrPauseAndRetryAccept` (`service.go:507-541`). Two consecutive `fill_form` steps have compatible schemas, so a page-1 input such as `{"fields": []}` would also be accepted by an all-optional page 2. Page 2 would be submitted without ever being shown. The guard:

- New in `pkg/lib/authenticationflow/context.go`:

  ```go
  type formInputConsumption struct{ consumed bool }

  // WithFormInputConsumption installs a per-request marker. Call once per request, before the accept loop.
  func WithFormInputConsumption(ctx context.Context) context.Context
  // MarkFormInputConsumed records that a form consumed the request's raw input.
  func MarkFormInputConsumed(ctx context.Context)
  // IsFormInputConsumed reports whether a form already consumed the request's raw input.
  func IsFormInputConsumed(ctx context.Context) bool
  ```

- `Service.feedInput`, `feedSyntheticInput`, and `createNewFlow` (`service.go`) call `ctx = WithFormInputConsumption(ctx)` before their `for shouldAccept` loop. The marker then survives `ErrPauseAndRetryAccept` retries.
- `IntentFillForm.ReactTo` at `len(nodes)==0`, when not prefilled:
  - If `IsFormInputConsumed(ctx)`, return `authflow.ErrIncompatibleInput`. `doAccept` then stops and persists the flow at this form.
  - Otherwise call `MarkFormInputConsumed(ctx)` before returning `NodeDoFillForm`.
- The prefilled path, an identify input that carries `fields`, also calls `MarkFormInputConsumed(ctx)`. A later `fill_form` therefore never consumes the identify input.

```go
type inputFillForm interface { GetFormFields() []FormFieldInput }
```

`CanReactTo`:

| Condition | Return |
|---|---|
| `IsUpdatingExistingUser && len(nodes)==0` | `nil, ErrEOF`. The form is skipped under account linking. |
| `len(nodes)==0 && IsSubmittedWithIdentification` | `nil, nil` |

| `len(nodes)==1` | `nil, nil` |
| otherwise | `nil, ErrEOF` |

`ReactTo`:

- At `len(nodes)==0`:
  - `fields` is `i.SubmittedFields` when `IsSubmittedWithIdentification`. Otherwise it comes from `AsInput(input, &inputFillForm)`, and anything else is `ErrIncompatibleInput`.
  - Apply the consumption guard above.
  - Return `authflow.NewNodeSimple(&NodeDoFillForm{UserID: i.UserID, JSONPointer: i.JSONPointer, Fields: fields})`. `appendNode` applies its run effect immediately, inside the request's transaction.
  - Clear `i.SubmittedFields`, because the node now holds the only copy.
- At `len(nodes)==1`: return `NewNodeFormPostSubmitted(ctx, deps, flows, &NodeFormPostSubmittedOptions{UserID: i.UserID, Form: form, Fields: node.Fields})`. `node` is the `NodeDoFillForm` at `flows.Nearest.Nodes[0]`.

`OutputData`:

1. `user := deps.Users.Get(ctx, i.UserID, config.RoleEndUser)`.
2. `NewFillFormDataForm(ctx, deps, form, user)`.
3. Return `NewFillFormData(...)`.

`i.form(deps, flows)` calls `findNearestFlowObjectInFlow`, then `authflow.FlowObject(root, i.JSONPointer)`, then `formFromFlowObject`.

New file `node_do_fill_form.go`:

```go
type NodeDoFillForm struct {
	UserID      string           `json:"user_id,omitempty"`
	JSONPointer jsonpointer.T    `json:"json_pointer,omitempty"` // the form's flow object
	Fields      []FormFieldInput `json:"fields,omitempty"`
	SkipUpdate  bool             `json:"skip_update,omitempty"`
}
```

It implements:

- `NodeSimple`
- `EffectGetter`
- `MilestoneDidFillForm`, with method `MilestoneDidFillForm() (skipped bool)`, which returns `n.SkipUpdate`.
- `MilestoneSwitchToExistingUser`, which sets `SkipUpdate = true`. Account linking rewrites the flow to an existing user after the form was submitted (`intent_account_linking.go:161-199`). The spec skips forms in that case. Without the flag, the run effect would replay against a user ID that is never created and break every later request.

Its one `RunEffect`:

1. If `SkipUpdate`, it does nothing.
2. Otherwise, it resolves the form with `formFromFlowObject(authflow.FlowObject(root, n.JSONPointer))` and calls `std, custom := formFieldsToAttrs(deps.Config, form, n.Fields)`.
3. `deps.StdAttrsService.UpdateStandardAttributesWithList(ctx, config.RoleEndUser, n.UserID, std)`
4. `deps.CustomAttrsService.UpdateCustomAttributesWithList(ctx, config.RoleEndUser, n.UserID, custom)`

Steps 3 and 4 emit no events. Each is skipped when its list is empty. Only the submitted `Fields` are persisted; attribute lists are derived from them.

New file `node_form_post_submitted.go`. It is modelled on `node_post_identified.go`:

```go
type NodeFormPostSubmittedOptions struct {
	UserID string
	Form   *config.AuthenticationFlowForm
	Fields []FormFieldInput
}

func NewNodeFormPostSubmitted(ctx context.Context, deps *authflow.Dependencies, flows authflow.Flows, opts *NodeFormPostSubmittedOptions) (authflow.ReactToResult, error)

type NodeFormPostSubmitted struct {
	IsInvoked bool `json:"is_invoked"`
}
```

`NewNodeFormPostSubmitted` does the following:

1. `authCtx := GetAuthenticationContext(ctx, deps, flows)`.
2. Build `payload := &blocking.AuthenticationFormPostSubmittedBlockingEventPayload{UserRef: model.UserRef{Meta: model.Meta{ID: opts.UserID}}, AuthenticationContext: *authCtx, Form: makeSubmittedForm(opts.Form, opts.Fields)}`:
   - `makeSubmittedForm` lists every form field in order.
   - `Value` is the submitted value, or nil when the field is absent.
3. `e := deps.Events.PrepareBlockingEventWithTx(ctx, payload, event.PrepareBlockingEventOptions{})`. The `user` is resolved here, inside the transaction where `NodeDoFillForm`'s run effect has already been applied. That gives the spec's "user with every attribute submitted so far applied".
4. Return `&authflow.NodeReactToResult{Node: NewNodeSimple(n), DelayedOneTimeFunction: fn}`. `fn` calls `deps.Events.DispatchEventWithoutTx(ctx, e)` and then sets `n.IsInvoked = true`.

`CanReactTo` returns `ErrEOF` once invoked, else `ErrPauseAndRetryAccept`. `ReactTo` returns `ErrEOF`.

On rejection, `processAcceptResult` returns the `HookDisallowed` error, and `feedInput` returns before `Store.CreateFlow`. So neither node is persisted, the state token stays valid, and the flow stays in the step. This is the same mechanism `authentication.post_identified` uses.

### 4.3 Events when the flow finishes

New file `utils_fill_form.go`:

```go
// dispatchUserProfileUpdateIfFormFilled dispatches user.profile.pre_update and user.profile.updated once if any form was submitted in the flow.
func dispatchUserProfileUpdateIfFormFilled(ctx context.Context, deps *authflow.Dependencies, flows authflow.Flows, userID string) error
```

It returns nil unless some `m` in `authflow.FindAllMilestones[MilestoneDidFillForm](flows.Nearest)` has `!m.MilestoneDidFillForm()`. It searches `flows.Nearest`, not `flows.Root`: account linking nests an `IntentLoginFlow` inside a signup flow (`intent_account_linking.go:139-143`), and that nested login must not count the outer signup's (skipped) forms. When there is a non-skipped form, it calls `deps.Events.DispatchEventOnCommit` with:

1. `&blocking.UserProfilePreUpdateBlockingEventPayload{UserRef: {ID: userID}}`
2. `&nonblocking.UserProfileUpdatedEventPayload{UserRef: {ID: userID}}`

`AdminAPI` is false, so `triggered_by` is `user`.

It has exactly two callers. Each is a new `OnCommitEffect` added to the root intent's `GetEffects`. `finishFlow` runs these effects when the flow finishes.

Resulting order for one identify input that includes the form:

1. `MakeInput` validates the login ID schema, the `fields` schema, and the constraints.
2. `IntentCreateIdentityLoginID` → `NodeDoCreateIdentity` → `NodePostIdentified`. The `authentication.post_identified` hook is dispatched.

- `UserID()` returns `UserRef.ID`.
- `GetTriggeredBy()` returns `TriggeredByTypeUser`.

The response schema is registered in `init()` with `event.RegisterResponseSchemaValidator`. It is its own part of `GetBaseHookResponseSchema()` and does not reference `BaseHookResponseSchema`, because that schema's `is_allowed: false` branch has `additionalProperties: false`:

```json
{
  "oneOf": [
    { "type": "object", "additionalProperties": false, "required": ["is_allowed"],
      "properties": { "is_allowed": { "const": true } } },
    { "type": "object", "additionalProperties": false, "required": ["is_allowed"],
      "properties": {
        "is_allowed": { "const": false },
        "title": { "type": "string" },
        "reason": { "type": "string" },
        "reasons": { "type": "array", "items": { "$ref": "#/$defs/FormHookResponseReason" } } } }
  ]
}
```

`FormHookResponseReason` is an object with `additionalProperties: false` and `required: [type, field, message]`:

- `type`: `enum ["invalid_form_field"]`. An unknown type is invalid, which gives `HookInvalidResponse`.
- `field`: an object with `additionalProperties: false` and `required: [user_profile]`. `user_profile` has `required: [pointer]` and a string `pointer`.
- `message`: a string.

`pkg/lib/config/hook.go`: add `"authentication.form.post_submitted"` to the blocking event enum. Add a fixture in `pkg/lib/config/testdata/hook_tests.yaml`.

## 6. Compatibility and deployment

| Concern | Behavior |
|---|---|
| Existing flows | No `fill_form` and no `form`, so no new nodes or events. |
| `fill_in_user_profile` | Unchanged. Deprecated in Go comments only. Not documented. |
| Flow state in Redis | New node and intent kinds are registered by `init()`. Old state has none of them. A state created by a new pod and read by an old pod during a rolling deploy fails with an unknown kind. This only affects projects that already use the new keys, which an old pod rejects at config load anyway. |
| `IntentSignupFlowStepIdentify` JSON | New fields are `omitempty`, so old state decodes with zero values. Zero values mean the form is not prefilled, which only matters for branches that have a form. |
| Hook error info | `reasons` is added only for the new event. |
| Config changed during a flow | Run effects replay on every request against the current config. If a form's attribute becomes non-fillable, a constraint is tightened, or the step is removed while a flow is in progress, the next input fails with the error of that write (`ValidationFailed`, an access-control error, or the existing panic when a flow object no longer resolves, as every other intent does). The end-user restarts the flow. This matches how existing steps react to mid-flow config changes. |
| Flow state | Submitted values (PII) are persisted in flow state in Redis until the flow expires, like login IDs already are. They are stored once: in `NodeDoFillForm.Fields`, or transiently in the identify intent until it hands them to `IntentFillForm`. |
| Breaking changes | None. All behavior is opt-in through new config keys. No `docs/BREAKING-CHANGES.md` entry. |

## 8. Fixed behavioral decisions

- A form may appear anywhere after an identify step on every path, in all three flow types. In login flows it may come before `authenticate`.
- Accepted trade-off: a login form placed before `authenticate` returns the user's current values in `fill_form_data` to anyone who enters that login ID, and its hook sees the user. The project owner controls flow placement. Writes are still committed only when the flow finishes, after authentication.
- Forms run after `select_account` like any other later step: `select_account` is a configured login identify branch, and the flow continues through that branch's nested steps and the later top-level steps (`intent_login_flow_step_identify.go`), so no special handling is needed.
- A form never consumes a raw input that another form in the same request already consumed.
- `triggered_by` for the finish-time `user.profile.pre_update` is `user`. Portal edits keep `admin_api`.
- Reasons with unknown keys are kept.
- The identify-step form runs after login-ID processing, standard-attribute population, and the login-hint check, and before the branch's nested steps.
