# Resource Indicator Part 6 — Biometric authentication

Spec: [docs/specs/biometric.md — Resource Indicators](../../specs/biometric.md#resource-indicators), [Access Token Audience Binding — New grant](../../specs/access-token-audience-binding.md#new-grant).

Depends on Part 5 (`resourceScopesForIssuance` as a package function).

## 1. Goal and scope

`grant_type=urn:authgear:params:oauth:grant-type:biometric-request`:

| Action | `resource` |
|---|---|
| `authenticate` | Optional. Checked as at `/oauth2/authorize` for the requesting client. The issued refresh token is bound to it. |
| `setup` | Rejected with `invalid_request`; setup issues no token. |

Out of scope: action `authenticate_app2app` (not implemented on the server).

This part adds two helpers that Part 7 reuses.

## 2. Helpers

`pkg/lib/oauth/handler/resource_access_policy.go`:

### 2.1 `newGrantScopes`

```go
// newGrantScopes checks resource and scope on a token request that creates
// a grant, as /oauth2/authorize would. defaultScopes is used when scope is
// omitted. See docs/specs/access-token-audience-binding.md § New grant.
func newGrantScopes(
	ctx context.Context,
	svc ResourceAccessPolicyService,
	issuer string,
	client *config.OAuthClientConfig,
	resourceURI string,
	requestedScopes []string,
	defaultScopes []string,
) (resourceID string, scopes []string, err error)
```

1. If `resourceURI != ""`:
   1. `strings.HasPrefix(resourceURI, issuer)` → `protocol.NewError("invalid_target", "resource URI must not be a prefixed by authgear endpoint")` (same text as `AuthorizationHandler.validateResource`).
   2. `resource, known, allowed, err := resourceScopes(ctx, svc, client, resourceURI)`; return `err` (already `errResourceNotAvailable()` when the Resource is missing or does not allow the client). `resourceID = resource.ID`.
2. `len(requestedScopes) == 0` → `scopes = defaultScopes`.
3. Else `oauth.ValidateScopesByClientConfig(requestedScopes, known)` → return its error; `scopes = oauth.GrantedScopes(client, requestedScopes, allowed)`.

`known` and `allowed` are nil without `resource`, so a Resource Scope without `resource` fails with `invalid_scope`, as today.

### 2.2 `checkOfflineFullAccessScopes`

```go
// checkOfflineFullAccessScopes rejects a biometric or anonymous grant that
// would issue no refresh token or no full-access.
func checkOfflineFullAccessScopes(scopes []string) error
```

Returns `protocol.NewError("invalid_scope", "offline_access and full-access must be requested")` unless `oauth.ContainsAllScopes(scopes, []string{oauth.OfflineAccess, oauth.FullAccessScope})`. It replaces the inline check in `handleBiometricAuthenticate`, with the same message.

## 3. Runtime changes

`pkg/lib/oauth/handler/handler_token.go`.

`handleBiometricRequest`, `case string(identitybiometric.RequestActionSetup)`: before `handleBiometricSetup`, if `r.Resource() != ""` return `protocol.NewError("invalid_request", "resource is not supported for biometric setup")`.

`handleBiometricAuthenticate`, in order:

1. `r.DeviceInfo()` (unchanged).
2. New, **before `Graphs.DryRun`**, so an invalid request authenticates nobody:
   ```go
   resourceID, scopes, err := newGrantScopes(ctx, h.ResourceAccessPolicyService, h.IDTokenIssuer.Iss(), client, r.Resource(), r.Scope(),
       []string{oauth.ScopeOpenID, oauth.OfflineAccess, oauth.FullAccessScope})
   ```
   then `checkOfflineFullAccessScopes(scopes)`.
3. `DryRun`, rate limit, `Graphs.Run` (unchanged).
4. Remove the old `scopes` / `requestedScopes` block and the inline full-access check.
5. `h.Authorizations.CheckAndGrant(ctx, client.ClientID, info.UserID, resourceID, scopes)`.
6. `IssueOfflineGrantOptions{..., ResourceURI: r.Resource()}`.
7. `oauth.PrepareUserAccessGrantOptions{..., ResourceURI: r.Resource()}`.

The encoder already sets `aud` from `ResourceURI` and forces a JWT (`pkg/lib/oauth/token_encoding.go`). Later refreshes use the `refresh_token` path, which reads `ResourceURI` from the refresh token.

## 4. Compatibility

- Without `resource`, every request behaves as today.
- Validation now runs before authentication. A request with an invalid `scope` used to authenticate and then fail; now it fails first. The response is the same.

## 5. Tests

Unit (Convey, package `handler`), in `resource_access_policy_test.go`, for `newGrantScopes`:

- no `resource`, no `scope` → defaults, `resourceID == ""`
- no `resource`, `scope` has a Resource Scope → `invalid_scope`
- `resource` under the issuer → `invalid_target`
- Resource not allowing the client's category → `invalid_target`
- `resource` + `scope` with an allowed and a disallowed Scope → the disallowed one dropped, `resourceID` set
- unknown scope → `invalid_scope`

E2E helper: new `e2e/pkg/testrunner/biometric.go`, modelled on `app2app.go` (one process-wide ES256 key, `kid` matching `^[-\w]{8,64}$`), registered in `makeTemplateFuncMap` (`e2e/pkg/testrunner/testcase.go`):

- `generateBiometricRequestJWT(challenge string, action string)`: header `typ: vnd.authgear.biometric-request`, `alg: ES256`, `kid`, plus `jwk` when `action == "setup"`; payload `challenge`, `action`, `device_info: {}`.

E2E test: new `e2e/tests/resource_indicator/biometric.test.yaml`. Config: `authentication.identities: [login_id, biometric]`; Resource R allowing static first-party with Scope `read:orders`. Challenges come from `POST /oauth2/challenge` with `purpose: biometric_request`.

| Step | Expect |
|---|---|
| Log in (password), exchange the code | access token |
| Setup with `Authorization: Bearer <access token>` | 200 |
| Setup with `resource=R` | `invalid_request` |
| Authenticate with `resource=R`, `scope=openid offline_access https://authgear.com/scopes/full-access read:orders` | 200, `scope` contains `read:orders` |
| Refresh that token with `resource=R` | 200 (proves the binding; an unbound token gets `invalid_target`) |
| Authenticate with `resource` of a Resource that does not allow static first-party | `invalid_target` |
