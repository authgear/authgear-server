# Resource Indicator Part 8 — App2app

Spec: [docs/specs/app2app.md — Resource Indicators](../../specs/app2app.md#resource-indicators), [Access Token Audience Binding — Derived grant](../../specs/access-token-audience-binding.md#derived-grant).

Depends on Part 5 (the app2app code carries the original refresh token's project-level scopes only).

## 1. Goal and scope

`grant_type=urn:authgear:params:oauth:grant-type:app2app` gains an optional `resource`. The original refresh token is the one presented; the new client is `client_id`.

| `resource` | Code |
|---|---|
| Omitted | Not bound; no Resource Scopes (Part 5) |
| The Resource the presented refresh token is bound to, and it allows both clients' categories | Bound to it; carries the presented refresh token's Scopes of it that the policy grants to both clients |
| Anything else | `invalid_target` |

The code exchange needs no change: `doIssueTokensForAuthorizationCode` reads `code.AuthorizationRequest.Resource()`, applies the subset rule, and re-reads the policy for the new client.

Out of scope: `biometric-request` action `authenticate_app2app` (not implemented), SDK changes.

This part adds a helper that Part 9 reuses.

## 2. Helper

`pkg/lib/oauth/handler/resource_access_policy.go`:

```go
// derivedGrantResourceScopes returns the Resource Scopes a derived grant
// carries for resourceURI. originals maps each Resource URI an original
// refresh token is bound to ("" for unbound) to its scopes. See
// docs/specs/access-token-audience-binding.md § Derived grant.
func derivedGrantResourceScopes(
	ctx context.Context,
	svc ResourceAccessPolicyService,
	originalClient *config.OAuthClientConfig,
	newClient *config.OAuthClientConfig,
	originals map[string][]string,
	resourceURI string,
) (resourceID string, resourceScopes []string, err error)
```

1. `resourceURI == ""` → `"", nil, nil`.
2. `held, ok := originals[resourceURI]`; `!ok` → `protocol.NewError("invalid_target", "resource is not bound to the original session")`.
3. `_, _, allowedOriginal, err := resourceScopes(ctx, svc, originalClient, resourceURI)` → return `err` (`errResourceNotAvailable()` if the Resource is gone or no longer allows the original client).
4. `resource, _, allowedNew, err := resourceScopes(ctx, svc, newClient, resourceURI)` → return `err`.
5. `resourceScopes = slice.Filter(held, func(s string) bool { return oauth.IsResourceScope(s) && slices.Contains(allowedOriginal, s) && slices.Contains(allowedNew, s) })`; return `resource.ID, resourceScopes, nil`.

The caller adds its own project-level scopes.

## 3. Runtime changes

`TokenHandler.handleApp2AppRequest` (`handler_token.go`). After Part 5 it computes `scopes` as the presented refresh token's scopes minus Resource Scopes. Change, after the device-key JWT is verified:

```go
// FIXME(DEV-1430): The new scopes should be validated against the new client
projectScopes := slice.Filter(offlineGrantSession.Scopes, func(s string) bool { return !oauth.IsResourceScope(s) })
resourceID, resourceScopes, err := derivedGrantResourceScopes(ctx, h.ResourceAccessPolicyService, originalClient, client,
	map[string][]string{offlineGrantSession.ResourceURI: offlineGrantSession.Scopes}, r.Resource())
if err != nil {
	return nil, err
}
scopes := append(projectScopes, resourceScopes...)
```

Then:

1. `CheckAndGrant(ctx, client.ClientID, userID, resourceID, scopes)`.
2. `artificialAuthorizationRequest["scope"] = strings.Join(scopes, " ")`.
3. If `r.Resource() != ""`: `artificialAuthorizationRequest["resource"] = r.Resource()`.

## 4. Compatibility

Requests without `resource` behave as after Part 5.

## 5. Tests

Unit (Convey, package `handler`), in `resource_access_policy_test.go`, for `derivedGrantResourceScopes`. Extend `stubResourceScopeService` only if a case needs two Resources.

- empty `resourceURI` → nothing
- `resourceURI` not in `originals` → `invalid_target`
- Resource allows the original client's category but not the new one's (static first-party vs `third_party_app`) → `invalid_target`, and the reverse
- Scope allowed for only one of the two categories → dropped
- held project-level scopes are not returned

E2E: `e2e/tests/oidc/app2app_resource.test.yaml`. Both e2e clients are static first-party, so the two-category check is covered by the unit tests only. Add:

| Step | Expect |
|---|---|
| App2app with `resource=R` from the R-bound refresh token | 200; redeemed token's `scope` contains `read:orders`; refresh with `resource=R` → 200 |
| App2app with an unrelated Resource | `invalid_target` |
| App2app with `resource=R` from an unbound refresh token | `invalid_target` |
