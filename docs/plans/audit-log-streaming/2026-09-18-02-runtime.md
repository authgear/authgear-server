# Audit Log Streaming — Part 02: Runtime

Implements the delivery path of [`docs/specs/audit-log-streaming.md`](../../specs/audit-log-streaming.md), on top of [part 01](./2026-09-18-01-config.md).

## Goal / scope

After this part the feature works end to end: a persisted audit log entry is queued in Redis, and once a minute the background worker takes each project's queue as a batch, encodes it as RFC 5424 and writes it to every configured stream.

Covered here: the Redis queue and its Lua scripts, the producer in `audit.Sink`, the `backgroundjob.Runnable` that drains and delivers, the RFC 5424 encoder, framing, the TCP/TLS transport, and the wiring in the auth server, the portal and the background binary.

Part 03 adds e2e coverage.

## 1. Which entries are streamed

The spec's rule is "streamed if and only if it is persisted as an audit log". In this codebase that resolves to a single insertion point.

`_audit_log` has exactly two writers:

- `pkg/lib/audit/sink.go:47` — `Sink.ReceiveNonBlockingEvent`, the tenant-visible path. Blocking events are never audited (`ReceiveBlockingEvent` returns nil unconditionally), and a non-blocking event is audited iff `payload.ForAudit()` is true. All 125 non-blocking payload types in the repo return true, so this is every non-blocking event, including the 16 `project.*` types the portal binary emits into the tenant's audit DB.
- `pkg/siteadmin/service/audit.go:122` — builds an `audit.WriteStore` inline, bypassing `Sink`, and records under the **portal's** app ID (`audit.go:73`), not the tenant's.

The producer is wired into `Sink` only. That yields exactly the set retrievable by a tenant's Admin API `auditLogs` query: `project.*` streams, `site_admin.*` does not.

## 2. Design

An entry is enqueued to Redis when it is persisted. A `backgroundjob.Runnable` in the background worker drains the queues once a minute and delivers each project's batch.

### 2.1 Why a queue and a runner, not in-process delivery

The obvious alternative is for `Sink` to hand the entry to a per-stream goroutine that owns a long-lived TCP connection. That is how the hook sink delivers non-blocking webhooks — one goroutine per event around an `http.Client` (`pkg/lib/hook/hook_web.go:92`). It was the original plan for this feature, and the queue is better on four counts:

- **Connection count.** A per-process pool holds one connection per (process × project × stream). With N auth-server replicas and M streaming projects that is N×M connections into customer collectors. Delivering from the background worker makes it M, and because each delivery dials, writes the batch and closes, they are not even held open between ticks.
- **Buffer durability.** An in-memory buffer silently discards whatever it holds on every rolling deploy. A Redis queue does not.
- **Ordering.** Per-process sockets can only promise per-process order, which is why the spec previously carried "There is no order guarantee across processes". One drainer writing a batch sequentially gives total order, so the spec now promises it outright.
- **Wiring.** An in-process pool needs a field on two different `RootProvider`s, a shutdown hook in two binaries, and a second pool for the portal, which has its own dependency graph. Producing to Redis needs a `globalredis.Handle`, which both already have.

What it costs is one Redis write per audit entry for streaming-enabled projects, and a dependency on the background worker being deployed. Both are stated in §8.

This is not `pkg/lib/infra/redisqueue`. That queue is built for durable, retryable, individually-tracked tasks: `Producer.EnqueueTask` writes a task key with `SetNX` and then `LPush`es a pointer to it (`producer.go:49-77`), and the consumer `BRPOP`s one task at a time. Streaming wants the opposite — no durability beyond a minute, no retry, no per-entry identity, and whole-batch delivery. A single list plus a Lua drain is both cheaper per entry and a closer fit.

### 2.2 Package layout

New package `pkg/lib/telemetry/auditlogstreaming`.

| File | Contents |
|---|---|
| `constants.go` | the tunables |
| `queue.go` | Redis keys, the Lua scripts, `Producer`, `Consumer` |
| `resolve.go` | `ResolvedStream`, resolution from config + secret |
| `encoder.go` | RFC 5424 message building, severity, SD escaping, framing |
| `hostname.go` | the project's RFC 5424 HOSTNAME, from `http.public_origin` |
| `transport.go` | dialing plaintext TCP and TLS, writing a batch |
| `runnable.go` | the `backgroundjob.Runnable` |
| `deps.go` | wire sets |

Runtime types stay separate from the `pkg/lib/config` types: config structs describe the document, `ResolvedStream` describes what the sender needs (parsed certificates, a resolved `*x509.CertPool`, and a facility already translated from `config.SyslogFacility`'s name (e.g. `local0`) to the `int` code PRI needs, via `SyslogFacility.Code()`).

### 2.3 Constants — `constants.go`

```go
const (
	// maxQueueLength bounds a single project's queue. Beyond it the oldest
	// queued entry is dropped.
	maxQueueLength = 10000

	// queueTTL expires a queue that nothing drains, so a background worker
	// that is not running cannot pin memory forever.
	queueTTL = 5 * time.Minute

	dialTimeout  = 5 * time.Second
	writeTimeout = 30 * time.Second
)
```

`maxQueueLength` is reached only when a project produces more than 10000 entries within one interval, or when delivery has stopped running. At the few kilobytes per entry the spec describes, 10000 entries is roughly 40 MB for one project at its worst, and the ceiling applies per project rather than globally so that a busy tenant cannot evict a quiet tenant's entries. Aggregate worst case is bounded by (streaming-enabled projects × 40 MB), and the feature config gates which projects those are.

`writeTimeout` covers a whole batch, not one message, which is why it is larger than a per-entry timeout would be.

The delivery interval is **not** here — it is environment config, see §7.3.

## 3. Redis model

### 3.1 Keys

Both in **global Redis** (`globalredis.Handle`), because the drainer is a single global worker and the keys are not app-scoped in the `app:<id>:` sense. This follows `RedisKeyForQueue` in `pkg/lib/infra/redisqueue/task.go:53`, which is likewise a global key with the app ID carried in the payload.

| Key | Type | Contents |
|---|---|---|
| `audit-log-stream:pending` | SET | app IDs with a non-empty queue |
| `audit-log-stream:queue:<app_id>` | LIST | entry JSON, oldest at head |

```go
func redisKeyPending() string { return "audit-log-stream:pending" }
func redisKeyQueue(appID string) string {
	return fmt.Sprintf("audit-log-stream:queue:%v", appID)
}
```

The list is built with `RPUSH`, so index 0 is the oldest and `LRANGE 0 -1` is already chronological. `LTRIM -maxQueueLength -1` then keeps the newest N and discards from the head, which is the "drop oldest" rule.

The pending set exists so the drainer knows which projects to visit without a `SCAN` over the keyspace on every tick.

### 3.2 Script plan

`Redis_6_0_Cmdable` (`pkg/lib/infra/redis/redis_6_0.go`) is the allowed command surface, and it has no `LRange`, `LTrim`, `RPush` or `LPop`. It does expose `Eval`/`EvalSha`, and the repo already drives Lua through `goredis.NewScript` in `ratelimit/gcra.go`, `lockout/record.go` and `usage/limit.go`. All queue access therefore goes through scripts, which also makes each operation atomic.

Three scripts, defined in `queue.go` as package-level `goredis.NewScript` values and run with `.Run(ctx, conn, keys, args...)`.

#### `enqueueScript`

| | |
|---|---|
| KEYS | `1` queue key, `2` pending key |
| ARGV | `1` entry JSON, `2` max length, `3` TTL seconds, `4` app ID |
| Returns | nothing meaningful |

```lua
redis.call("RPUSH", KEYS[1], ARGV[1])
redis.call("LTRIM", KEYS[1], -tonumber(ARGV[2]), -1)
redis.call("EXPIRE", KEYS[1], tonumber(ARGV[3]))
redis.call("SADD", KEYS[2], ARGV[4])
redis.call("EXPIRE", KEYS[2], tonumber(ARGV[3]))
return redis.status_reply("OK")
```

Called once per persisted audit entry of a streaming-enabled project, from `Producer.Enqueue`. On error the producer logs and returns; the entry is not streamed and nothing fails.

#### `claimPendingScript`

| | |
|---|---|
| KEYS | `1` pending key |
| ARGV | none |
| Returns | array of app IDs |

```lua
local apps = redis.call("SMEMBERS", KEYS[1])
redis.call("DEL", KEYS[1])
return apps
```

Called once per tick, at the start of `Runnable.Run`. Claiming and clearing together means a producer that re-adds an app between the two would otherwise be lost; because `SADD` happens on every enqueue, the app is simply re-added by the next entry and picked up on the next tick. An app that is claimed but whose queue is already empty yields an empty batch, which is harmless.

#### `drainScript`

| | |
|---|---|
| KEYS | `1` queue key |
| ARGV | none |
| Returns | array of entry JSON, oldest first |

```lua
local items = redis.call("LRANGE", KEYS[1], 0, -1)
redis.call("DEL", KEYS[1])
return items
```

Called once per claimed app. Taking and clearing in one script is what implements the spec's "Taking the batch clears the queue, whether or not the send succeeds. Nothing accumulates across deliveries." A failure after this point drops the batch by construction — there is nothing left to retry from.

### 3.3 Single drainer

`claimPendingScript` and `drainScript` are atomic, so two background replicas never receive the same entry. They could still split one tick's work and deliver concurrently, which would interleave the order and open two connections per stream.

`Runnable.Run` therefore takes a redsync mutex for the length of a tick, using the `Redsync` instance the Redis pool already builds (`pkg/lib/infra/redis/pool.go:97`, reachable through the handle as at `handle.go:55`). Mutex name `audit-log-stream:drain`, expiry twice the interval. A replica that fails to acquire it returns immediately and waits for the next tick.

## 4. Producer

### 4.1 `Producer` — `queue.go`

Request-scoped, constructed per request by wire, holding only pointers.

```go
type Producer struct {
	AppID    config.AppID
	Streams  []*config.TelemetryAuditLogStreamConfig
	Disabled bool
	Redis    *globalredis.Handle
}

func (p *Producer) Enqueue(ctx context.Context, e *event.Event)
```

`Enqueue` never returns an error and never blocks on anything but the Redis round trip:

1. `if p.Disabled || len(p.Streams) == 0 { return }`.
   `Disabled` is `*featureConfig.Telemetry.AuditLogs.Streaming.Disabled`. This is the runtime half of the feature gate: a project whose plan was downgraded stops streaming immediately, without waiting for someone to edit `authgear.yaml`. Part 01 §1.11 only stops *new* saves.
   It is also what keeps the Redis cost proportional to streaming-enabled projects rather than to all authentication traffic — a project with no streams performs no Redis work at all.
2. `payload, err := json.Marshal(e)`; on error, log and return. This is the spec's MSG, marshalled once and reused for every stream at delivery time.
3. Run `enqueueScript` with the two keys and the four arguments. On error, log and return.

The entry is stored as the marshalled `*event.Event` alone. The app ID is already in `e.Context.AppID` and in the key, so no envelope is needed.

### 4.2 Sink integration — `pkg/lib/audit/sink.go`

```go
type Sink struct {
	Database *auditdb.WriteHandle
	Store    *WriteStore
	Producer *auditlogstreaming.Producer
}
```

In `ReceiveNonBlockingEvent`, the call goes **after** the transaction returns successfully, replacing the current bare `if err != nil { return }` tail:

```go
	err = s.Database.WithTx(ctx, func(ctx context.Context) error {
		logEntry, err := NewLog(e)
		if err != nil {
			return err
		}
		return s.Store.PersistLog(ctx, logEntry)
	})
	if err != nil {
		return
	}

	s.Producer.Enqueue(ctx, e)

	return
```

This placement is what implements "streamed iff persisted":

- the `!payload.ForAudit()` early return is before it, so a non-audit event is not streamed;
- the `s.Database == nil` early return is before it, so a deployment with no audit database streams nothing;
- a failed transaction returns before it.

`Enqueue` returns nothing, so the sink's error behaviour is unchanged — streaming can never fail an end-user request.

## 5. Consumer

### 5.1 `Runnable` — `runnable.go`

Follows `accountdeletion.Runnable` (`pkg/lib/feature/accountdeletion/runnable.go:31-53`), which lists work across apps and then resolves each app's context.

```go
type AppContextResolver interface {
	ResolveContext(ctx context.Context, appID string, fn func(context.Context, *config.AppContext) error) error
}

type SenderFactory interface {
	MakeSender(appID string, appCtx *config.AppContext) Sender
}

type Runnable struct {
	Consumer           *Consumer
	AppContextResolver AppContextResolver
	SenderFactory      SenderFactory
}

func (r *Runnable) Run(ctx context.Context) error
```

`Run`, once per tick:

1. Acquire the redsync mutex (§3.3). Not acquired → return nil.
2. `appIDs, err := r.Consumer.ClaimPending(ctx)` — `claimPendingScript`.
3. For each `appID`:
   a. `events, err := r.Consumer.Drain(ctx, appID)` — `drainScript`. Empty → continue.
   b. `r.AppContextResolver.ResolveContext(ctx, appID, func(ctx, appCtx) error { ... })`, inside which:
      - read `appCtx.Config.AppConfig.Telemetry.AuditLogs.Streams`, the feature `Disabled` flag and the TLS materials from `appCtx.Config.SecretConfig`;
      - if disabled or no streams, return nil — the batch is already gone, which is correct: a project that stopped streaming between enqueue and drain does not deliver;
      - resolve the project's HOSTNAME once with `ResolveHostname(appCtx.Config.AppConfig.HTTP.PublicOrigin)` (§6.3);
      - `sender := r.SenderFactory.MakeSender(appID, appCtx)`; `sender.Send(ctx, events)`.
   c. An error from one app is logged and does not stop the loop. `Run` returns nil unless the claim itself failed, so one broken project cannot stop delivery for the rest.
4. Release the mutex.

Failure is per app and per stream, never per entry: there is no per-entry acknowledgement to act on.

### 5.2 `Sender` — `transport.go`

```go
type Sender interface {
	Send(ctx context.Context, events []*event.Event)
}

type SenderImpl struct {
	AppID    string
	Hostname string
	Streams  []*config.TelemetryAuditLogStreamConfig
	TLS      *config.TelemetryAuditLogStreamTLSMaterials
}

func (s *SenderImpl) Send(ctx context.Context, events []*event.Event)
```

`Send`, once per tick per app:

1. For each configured stream:
   a. `resolved, err := resolveStream(s.AppID, streamConfig, s.TLS)` — §6.1. On error, log and continue to the next stream.
   b. `conn, err := dial(ctx, resolved)` — §6.4. On error, log and continue to the next stream. The whole batch for this stream is dropped.
   c. `conn.SetWriteDeadline(now + writeTimeout)`.
   d. For each event in order: `frame := Frame(resolved.Syslog.Framing, EncodeRFC5424(&resolved.Syslog, s.Hostname, e, msg))`, accumulated into one `bytes.Buffer`, then written with a single `conn.Write`. One syscall per stream per tick rather than one per entry.
   e. `conn.Close()`.
2. Streams are independent: a failure of one does not affect the other, which is the spec's UC3 requirement.

`msg` is the raw JSON stored in Redis — the consumer keeps the original bytes alongside the decoded `*event.Event` so that MSG is byte-identical to what the producer marshalled, and is not re-marshalled with a different key order.

Connections are not pooled across ticks. At one delivery a minute, a fresh dial (and TLS handshake) per stream per tick is negligible, and it removes idle-connection, reconnect and backoff handling entirely.

## 6. Encoding and transport

### 6.1 Resolved runtime types — `resolve.go`

```go
type ResolvedStream struct {
	AppID string
	Name  string

	Address    string
	TLSEnabled bool
	// TLSClientCertificate is nil unless the stream declares client_certificate.
	TLSClientCertificate *tls.Certificate
	// TLSRootCAs is nil unless the stream declares certificate_authority,
	// in which case the system trust store is not consulted.
	TLSRootCAs *x509.CertPool

	Syslog ResolvedSyslog
}

type ResolvedSyslog struct {
	Format           config.SyslogFormat
	Framing          config.SyslogFraming
	Facility         int
	AppName          string
	StructuredDataID string
}
```

```go
func resolveStream(
	appID string,
	streamConfig *config.TelemetryAuditLogStreamConfig,
	materials *config.TelemetryAuditLogStreamTLSMaterials,
) (*ResolvedStream, error)
```

In order:

1. Reads `streamConfig.TCP.Address` and `streamConfig.TCP.TLS.Enabled`. Both are safe without nil guards: `SetFieldDefaults` materialises every nil struct pointer (part 01 §1.1).
2. If TLS is not enabled, returns with no TLS material, ignoring any secret item. Part 01 §1.7 deliberately does not reject such an item, so this branch is reachable in a healthy project and is the runtime half of "an item whose stream does not enable `tcp.tls` is ignored".
3. `item, ok := materials.Resolve(streamConfig.Name)`. On miss, returns with `TLSClientCertificate` and `TLSRootCAs` nil — the system trust store is used.
4. `item.CertificateAuthority` present → `pool := x509.NewCertPool()`, `pool.AppendCertsFromPEM([]byte(ca.Pem))`; error if nothing was appended.
5. `item.ClientCertificate` present → build a `tls.Certificate`:
   - the chain is every PEM block in `client_certificate.certificate.pem` (leaf first, then intermediates), decoded with repeated `pem.Decode` into `cert.Certificate [][]byte`;
   - the private key comes from the `JWK`, via `item.ClientCertificate.Key.Key.Raw(&privateKey)` into an `any`, the same call `pkg/lib/saml/service.go:911` uses;
   - `cert.PrivateKey = privateKey`, `cert.Leaf` parsed from the first block.
   An error here is returned, not panicked — unlike `X509Certificate.X509Certificate()`, which panics; this input reaches us from a secret file and a bad value must degrade the stream, not the worker.

Resolution happens once per stream per tick. At one tick a minute there is nothing to memoise.

### 6.2 Encoder — `encoder.go`

```go
func EncodeRFC5424(s *ResolvedSyslog, hostname string, e *event.Event, msg []byte) []byte
func Frame(framing config.SyslogFraming, syslogMsg []byte) []byte
func severity(t event.Type) int
func escapeSDParam(v string) string
```

`EncodeRFC5424` builds, into a single `bytes.Buffer`:

```
<PRI>1 TIMESTAMP HOSTNAME APP-NAME - authgear-audit-log [SD] MSG
```

- `PRI` = `s.Facility*8 + severity(e.Type)`.
- `VERSION` is the literal `1`.
- `TIMESTAMP` = `time.Unix(e.Context.Timestamp, 0).UTC().Format("2006-01-02T15:04:05Z")`. The event carries whole seconds, so there is no fractional part — do not use `time.RFC3339Nano`. This is the time the event occurred, not the time it is delivered, so batching does not change it.
- `HOSTNAME` = the argument, already resolved and sanitised by §6.3. It is the host of the project's `http.public_origin`, not the hostname of any Authgear process.
- `APP-NAME` = `s.AppName`.
- `PROCID` = `-`.
- `MSGID` = the constant `authgear-audit-log`. It does not carry the activity type: RFC 5424 caps MSGID at 32 characters and the longest activity type in the repo, `admin_api.mutation.unschedule_account_anonymization.executed`, is exactly 60.
- `STRUCTURED-DATA` = one element, `[` + `s.StructuredDataID` then, in this fixed order, each non-empty parameter as ` name="value"`:

  | Param | Source |
  |---|---|
  | `app_id` | `e.Context.AppID` |
  | `id` | `e.ID` |
  | `activity_type` | `string(e.Type)` |
  | `user_id` | `*e.Context.UserID`, omitted when the pointer is nil |
  | `client_id` | `e.Context.ClientID` |
  | `ip_address` | `e.Context.IPAddress` |

  then `]`. A parameter whose value is empty is omitted entirely.
- `MSG` = `msg` verbatim, with no BOM prefix.

`escapeSDParam` replaces `\` with `\\`, `"` with `\"`, and `]` with `\]`, in that order — backslash first, or the escapes introduced by the other two get double-escaped.

`severity` returns `4` for exactly `email.error`, `sms.error` and `whatsapp.error`, and `6` for everything else. The list is a package-level `map[event.Type]int`; a new activity type is `6` until it is added to that map.

`Frame`:

| `framing` | Output |
|---|---|
| `octet_counting` | `strconv.Itoa(len(syslogMsg))` + `" "` + `syslogMsg` |
| `newline` | `syslogMsg` + `"\n"` |

`newline` is safe for every entry without inspection: MSG is `encoding/json` output, so an LF inside a value is escaped as `\n`, and no other field of the message can contain an LF.

### 6.3 Hostname — `hostname.go`

HOSTNAME identifies the **project**, not the process that delivered the entry. With delivery in the background worker the process hostname would name the worker, which tells a receiver nothing; the host of `http.public_origin` names the project the entries belong to.

```go
// ResolveHostname returns the RFC 5424 HOSTNAME for a project.
func ResolveHostname(publicOrigin string) string {
	u, err := url.Parse(publicOrigin)
	if err != nil {
		return "-"
	}
	return sanitizeHostname(u.Hostname())
}
```

- `u.Hostname()` rather than `u.Host`, so a `public_origin` carrying a port (`http://app.localhost:4000`, as in local development and e2e) yields the bare host. RFC 5424 HOSTNAME is a hostname, FQDN or IP address, not an authority.
- `sanitizeHostname` returns `-` unless the value is 1-255 characters of printable US-ASCII (`0x21`-`0x7E`), which is what RFC 5424 permits. A project whose `public_origin` uses a non-ASCII internationalised domain therefore reports `-`; the project is still identifiable from the `app_id` structured-data parameter. Converting to punycode is deliberately not attempted.
- `http.public_origin` is required and format-validated (`pkg/lib/config/http.go:20`, format `http_origin`), so the parse failure branch is defensive rather than reachable through a saved config.

Called once per app per tick in `Runnable.Run`, from `appCtx.Config.AppConfig.HTTP.PublicOrigin`, and passed to `SenderImpl`. Not resolved per entry and not resolved at package init.

### 6.4 Dial — `transport.go`

```go
func dial(ctx context.Context, s *ResolvedStream) (net.Conn, error)
```

- `net.Dialer{Timeout: dialTimeout}`, `DialContext(ctx, "tcp", s.Address)`.
- When `s.TLSEnabled`, wrap with `tls.Client` using:
  - `MinVersion: tls.VersionTLS12` — the spec's "at least 1.2";
  - `ServerName` = the host part of `s.Address` via `net.SplitHostPort`, which part 01 §1.3 already validated as parseable;
  - `RootCAs: s.TLSRootCAs` — nil means the system trust store;
  - `Certificates: []tls.Certificate{*s.TLSClientCertificate}` when non-nil.
- Then `HandshakeContext(ctx)` so a hung handshake is bounded by the same deadline.

## 8. Compatibility and deployment behaviour

- **No SQL, no migration, no backfill.** The only new persisted state is two Redis keys with a 5-minute TTL.
- **New Redis keys.** `audit-log-stream:pending` and `audit-log-stream:queue:<app_id>`, both new, both in global Redis. Nothing reads keys of an older shape, so there is no dual-read or dual-write to arrange.
- **No API change.** No Admin API, portal GraphQL or Site Admin API payload or error changes.
- **No BREAKING-CHANGES entry.** A deployment that works today keeps working: with no `telemetry` section, `Producer.Enqueue` returns on its first line and the runner claims an empty set.
- **The background worker becomes load-bearing for this feature.** A deployment that does not run `authgear background` queues entries and delivers none of them; the queues expire after `queueTTL` and nothing else happens. This is recorded in the spec's Caveats. It is not a regression — the feature simply does not work — but it is the first feature whose *entire* function depends on that binary, so it is worth stating in release notes when the feature ships.
- **Mixed-version rollout.** Producers on the new binary enqueue; a background worker on the old binary ignores the keys, which then expire. Once the worker is upgraded, delivery starts. Entries produced during the gap are lost, which is within the at-most-once contract.
- **Multiple background replicas** are safe: the scripts are atomic and the redsync mutex means one replica delivers per tick.

## 9. Fixed behavioural decisions

1. The producer is wired into `audit.Sink` only. `site_admin.*` entries (`pkg/siteadmin/service/audit.go`) are **not** streamed: they are recorded under the portal's app ID and are not retrievable by a tenant's Admin API `auditLogs` query, which is the boundary this feature follows.
2. `project.*` entries, emitted by the portal binary into the tenant's audit DB, **are** streamed.
3. Delivery interval defaults to one minute and is set by `AUDIT_LOG_STREAMING_INTERVAL`.
4. The queue is bounded at 10000 entries per project, dropping the **oldest** on overflow, with a 5-minute TTL as a safety net against a worker that is not running.
5. Draining clears the queue whether or not the send succeeds. There is no retry and no dead-letter.
6. Connections are dialled per stream per tick and closed after the batch. Nothing is pooled.
7. RFC 5424 HOSTNAME is the host of the project's `http.public_origin` without its port, not the hostname of any Authgear process. A non-ASCII host reports `-` rather than being punycoded.
8. A stream whose TLS material fails to resolve is skipped for that tick; it does not fall back to a plaintext or unverified connection.
9. The feature gate is enforced at enqueue **and** at delivery, so a plan downgrade stops streaming without a config edit, and a batch queued before a downgrade is not delivered after it.
10. One redsync mutex serialises delivery across background replicas.
11. Failure logging plus Debug-level success logging, via `slogutil`, logger name `audit-log-streaming`. Enqueue failures, resolve failures, dial failures and write failures are logged with `app_id` and the stream `name`; a delivered batch is logged at Debug with its entry count. No metrics instrumentation — the stream `name` is a config identifier, not an observability surface.

## 11. Test plan

`pkg/lib/audit` and its neighbours use Convey; the new package's tests match that style per the `add-go-test` skill.

### 11.1 `encoder_test.go`

Pure, no I/O. Assert on exact bytes.

- a `user.authenticated` event with every context field populated produces the exact message in the spec's UC1 example, with `<134>` (facility 16, severity 6) and `myproject.authgear.cloud` as HOSTNAME.
- `ResolveHostname` returns `myproject.authgear.cloud` for `https://myproject.authgear.cloud`, strips the port from `http://app.localhost:4000` to give `app.localhost`, returns `-` for a host containing non-ASCII, and returns `-` for an unparseable origin. The port case is the one that matters in practice — local development and e2e both carry one.
- `facility: 0` and severity 6 → `<6>`; `facility: 23`, `email.error` → `<188>`.
- `severity` returns 4 for `email.error`, `sms.error`, `whatsapp.error`; 6 for `user.authenticated`, `usage.alert.triggered` and an invented `some.new.type`.
- a nil `Context.UserID` omits `user_id` entirely, rather than emitting `user_id=""`.
- empty `client_id` and `ip_address` are omitted; empty `app_id` is omitted.
- SD parameter values containing `"`, `\` and `]` are escaped, including a value containing all three and a value already containing `\"`, which must become `\\\"`.
- `structured_data_id` containing `^` round-trips unescaped.
- TIMESTAMP has no fractional seconds, ends in `Z`, and reflects `Context.Timestamp` rather than the current time — the case that proves batching does not rewrite event times.
- MSG is byte-identical to the supplied `msg` and is not BOM-prefixed.
- `Frame` with `newline` appends exactly one `\n`; with `octet_counting` the prefix equals `len(syslogMsg)` for a message containing multi-byte UTF-8, proving the count is bytes and not runes.

### 11.2 `resolve_test.go`

- TLS disabled → no TLS material even when a matching secret item exists.
- TLS enabled, no secret item → `TLSRootCAs` and `TLSClientCertificate` both nil.
- `certificate_authority` only → `TLSRootCAs` non-nil, `TLSClientCertificate` nil.
- `client_certificate` only → the reverse.
- both → both.
- a certificate chain with a leaf plus one intermediate produces two entries in `tls.Certificate.Certificate`.
- malformed CA PEM and a JWK that does not match the certificate each return an error rather than panicking.

### 11.3 `queue_test.go` — against a real Redis

The package's Redis tests follow the existing pattern for Redis-backed code in this repo (`pkg/lib/ratelimit`, `pkg/lib/lockout`), which exercise the Lua against a live instance rather than a mock, because the behaviour under test *is* the script.

- enqueue then drain returns the entries in the order they were enqueued, oldest first.
- drain clears the queue: a second drain returns empty.
- enqueueing `maxQueueLength + 10` entries leaves exactly `maxQueueLength`, and the entries that survived are the **newest** — the direct test of the drop-oldest rule.
- the pending set contains the app after one enqueue and is empty after `ClaimPending`.
- `ClaimPending` returns every app that enqueued, and an app that enqueues again after a claim is returned by the next claim.
- draining an app with no queue returns empty without error.
- both keys carry a TTL after enqueue.

### 11.4 `runnable_test.go`

- two apps queued → each app's batch is sent with that app's resolved streams and that app's HOSTNAME, and one app's failure does not prevent the other's delivery. The per-app HOSTNAME is the case that catches it being resolved once for the tick instead of once per app.
- an app whose feature config is `disabled: true` at drain time delivers nothing, even though the entries were enqueued while it was enabled.
- an app whose streams were removed between enqueue and drain delivers nothing and does not error.
- the redsync mutex is held for the tick: a second concurrent `Run` returns without draining.

### 11.5 `transport_test.go` — against an in-process `net.Listener`

- a batch of three entries arrives as three frames on one connection, in order, and the connection is closed afterwards.
- two streams both receive the whole batch; a stream whose dial fails does not prevent the other from receiving it.
- TLS: an in-process `tls.Listener` with a self-signed cert and a matching `certificate_authority` → delivered; a non-matching CA → the batch is dropped and the error is logged.
- mTLS: a listener with `ClientAuth: RequireAndVerifyClientCert` → delivered when the stream declares a `client_certificate` signed by the listener's client CA, refused when it does not.
- a listener that accepts and then stalls → the write deadline fires and the batch is dropped rather than hanging the tick.

### 11.6 `pkg/lib/audit/sink_test.go`

- an event with `ForAudit() == false` is neither persisted nor enqueued.
- `Database == nil` → not enqueued.
- a failing transaction → not enqueued.
- a successful transaction → enqueued exactly once.
- `Disabled: true` or no streams → not enqueued, and no Redis call is made.
