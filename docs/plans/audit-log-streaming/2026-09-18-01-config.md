# Audit Log Streaming — Part 01: Config

Implements the configuration surface of [`docs/specs/audit-log-streaming.md`](../../specs/audit-log-streaming.md).

## Goal / scope

After this part:

- `telemetry.audit_logs.streams` parses, defaults and validates in `authgear.yaml`.
- `telemetry.audit_logs.streams.tls` parses and validates in `authgear.secrets.yaml`.
- `telemetry.audit_logs.streaming.disabled` parses, merges field-level and gates saving in `authgear.features.yaml`.
- Nothing is streamed. No runtime behaviour changes.

Part 02 adds the Redis queue, the encoder, the transport and the background delivery. Part 03 adds e2e coverage.

This part is shippable on its own: a project can write the configuration, and it is accepted or rejected exactly as the spec says.

```go
// SyslogFacility names a syslog facility, matching the set redis.conf's
// syslog-facility setting accepts. See Code() for the RFC 5424 Table 1
// numeric code each name maps to.
type SyslogFacility string

const (
	SyslogFacilityUser   SyslogFacility = "user"
	SyslogFacilityLocal0 SyslogFacility = "local0"
	SyslogFacilityLocal1 SyslogFacility = "local1"
	SyslogFacilityLocal2 SyslogFacility = "local2"
	SyslogFacilityLocal3 SyslogFacility = "local3"
	SyslogFacilityLocal4 SyslogFacility = "local4"
	SyslogFacilityLocal5 SyslogFacility = "local5"
	SyslogFacilityLocal6 SyslogFacility = "local6"
	SyslogFacilityLocal7 SyslogFacility = "local7"
)

// Code returns f's numeric syslog facility code, per Table 1 in RFC 5424
// section 6.2.1. Schema validation restricts
// TelemetryAuditLogStreamSyslogConfig.Facility to exactly the named
// constants above, so every value reaching here has a case.
func (f SyslogFacility) Code() int {
	switch f {
	case SyslogFacilityUser:
		return 1
	case SyslogFacilityLocal0:
		return 16
	case SyslogFacilityLocal1:
		return 17
	case SyslogFacilityLocal2:
		return 18
	case SyslogFacilityLocal3:
		return 19
	case SyslogFacilityLocal4:
		return 20
	case SyslogFacilityLocal5:
		return 21
	case SyslogFacilityLocal6:
		return 22
	case SyslogFacilityLocal7:
		return 23
	default:
		panic("config: unknown syslog facility: " + string(f))
	}
}

type TelemetryAuditLogStreamSyslogConfig struct {
	Format           SyslogFormat   `json:"format,omitempty"`
	Framing          SyslogFraming  `json:"framing,omitempty"`
	Facility         SyslogFacility `json:"facility,omitempty"`
	AppName          string         `json:"app_name,omitempty"`
	StructuredDataID string         `json:"structured_data_id,omitempty"`
}

func (c *TelemetryAuditLogStreamSyslogConfig) SetDefaults() {
	if c.Facility == "" {
		c.Facility = SyslogFacilityLocal0
	}
	if c.AppName == "" {
		c.AppName = "authgear"
	}
	if c.StructuredDataID == "" {
		c.StructuredDataID = "authgear"
	}
}
```

`facility` is a string, not an integer: it names one of the facilities
redis.conf's `syslog-facility` setting accepts (`user`, `local0`-`local7`),
matching an operator's existing mental model rather than requiring them to
know RFC 5424's numeric table. `Code()` is the only place that table is
encoded, and it is called once, at resolve time (see the runtime plan).

`Streams` is a slice of pointers. `SetFieldDefaults` (`pkg/lib/config/default.go:16-22`) walks slices and calls `SetDefaults()` on each element's pointer, so `SetDefaults` on `*TelemetryAuditLogStreamSyslogConfig` is reached for every stream.

Note the consequence of `default.go:33-36`: the reflection walk instantiates every nil struct pointer. After defaulting, `stream.TCP`, `stream.TCP.TLS` and `stream.Syslog` are always non-nil, and `TCP.TLS.Enabled` is `false` when the block was absent. Part 02's resolver relies on this — it reads these fields without nil guards. Nothing else may rely on their nil-ness to mean "absent".

Three things in the schema are easy to get wrong and are deliberate:

- The third `allOf` clause is the `type` × `transport` combination matrix of the spec. Today the two enums have one value each, so the pair is already forced; the clause exists so that adding a second `transport` value does not silently make `syslog` + that transport valid. A new supported pair is added by extending the `then.properties.transport.enum` list, and a new row in the spec table.
- `app_name` is printable US-ASCII 1-48: `[!-~]` is exactly `0x21`-`0x7E`.
- `structured_data_id` is printable US-ASCII 1-32 excluding `=`, `]`, `"` and space. The ranges are `!`, `#`-`<`, `>`-`\`, `^`-`~`. The trailing `\` of the third range must be a regex-escaped backslash (`\\`), which in the JSON string literal is `\\\\`. The resulting regex is `^[!#-<>-\\^-~]{1,32}$`. Write it as shown; a single `\\` here produces `\^`, which silently means "an escaped caret" instead of the intended range and wrongly rejects `]`-free values containing `^`.

### 1.3 `x_host_port` format — `pkg/lib/config/formats.go`

`tcp.address` is `host:port` and part 02 derives the TLS `ServerName` from its host, so the shape is validated here rather than at dial time.

Add to the existing `func init()`:

```go
jsonschemaformat.DefaultChecker["x_host_port"] = FormatHostPort{}
```

```go
// FormatHostPort checks that the input is a "host:port" address.
type FormatHostPort struct{}

func (f FormatHostPort) CheckFormat(ctx context.Context, value any) error {
	str, ok := value.(string)
	if !ok {
		return nil
	}
	host, port, err := net.SplitHostPort(str)
	if err != nil {
		return err
	}
	if host == "" {
		return fmt.Errorf("expect non-empty host")
	}
	p, err := strconv.Atoi(port)
	if err != nil || p < 1 || p > 65535 {
		return fmt.Errorf("expect port in range 1-65535")
	}
	return nil
}
```

Following the convention of the other checkers in the file, a non-string value is not an error; `"type": "string"` in the schema enforces the type.

Per the spec's Caveats, the host is **not** checked against private or link-local ranges. This matches the existing treatment of hook URLs and is intentional.

### 1.7 Orphaned TLS material — tolerate at load, prune on save

There is **no** cross-validation between `telemetry.audit_logs.streams.tls` and the streams, in either direction. Specifically, nothing is added to `SecretConfig.Validate`.

That is a deliberate departure from the neighbouring checks in that function (`validateLDAPServerUserSecrets`, `validateSAMLServiceProviderCerts`). `SecretConfig.Validate` is called from `configsource/loader.go:49` on every config **load**, so an error there is a project that does not start. Rejecting an item whose `stream_name` no longer matches a stream would make removing a stream a two-step change that breaks the project if done in the wrong order — for a feature whose whole failure mode is otherwise "entries are not delivered".

Instead the treatment of `oauth.client_secrets` is followed: a leftover item is ignored, and it is cleaned up the next time `authgear.yaml` is saved.

- **At load**: an item whose `stream_name` matches no stream is ignored. An item whose stream exists but does not enable `tcp.tls` is also ignored. Part 02's resolver already reads the secret only for a stream with TLS enabled, so this needs no runtime code.
- **At save**: orphaned items are pruned.

#### Pruning — `pkg/portal/appresource/manager.go`

`ApplyUpdates0` already has the hook and the trigger condition. Lines 156-171 run `cleanupOrphanedResources` exactly when the update set contains `authgear.yaml`, for exactly this reason:

```go
	// Clean up orphaned resources if authgear.yaml is updated.
```

Add a sibling called from the same loop:

```go
func (m *Manager) cleanupOrphanedSecrets(manager *resource.Manager, cfg *config.Config) (*resource.ResourceFile, error)
```

Call site, inside the existing `for _, update := range updates { if update.Path == configsource.AuthgearYAML {` block, after the `cleanupOrphanedResources` call:

```go
			secretFile, err := m.cleanupOrphanedSecrets(newManager, cfg)
			if err != nil {
				return nil, err
			}
			if secretFile != nil {
				files = append(files, secretFile)
			}
```

`cleanupOrphanedSecrets`:

1. Build `keep := map[string]struct{}` from **every** `cfg.AppConfig.Telemetry.AuditLogs.Streams[i].Name`, regardless of `tcp.tls.enabled`.
2. Locate the app-level `authgear.secrets.yaml` (`fs.GetFsLevel() == resource.FsLevelApp`) via `manager.Filesystems()`, the same way `cleanupOrphanedResources` does. Return `nil, nil` when there is none.
3. `secretConfig, err := config.ParsePartialSecret(ctx, resrc.Data)` — the non-validating parser (`secret.go:36`), because the document being pruned may be exactly the one a validating parse would reject.
4. `idx, item, found := secretConfig.Lookup(TelemetryAuditLogStreamTLSMaterialsKey)`. Return `nil, nil` when not found.
5. Filter `*item.Data.(*config.TelemetryAuditLogStreamTLSMaterials)` down to items whose `StreamName` is in `keep`. If nothing was removed, return `nil, nil` — an unchanged file must not be rewritten, or every `authgear.yaml` save churns `authgear.secrets.yaml`.
6. If the filtered list is empty, drop the whole secret entry: `secretConfig.Secrets = append(secretConfig.Secrets[:idx], secretConfig.Secrets[idx+1:]...)`. Otherwise re-encode it into the item's `RawData`:

```go
	jsonData, err := json.Marshal(filtered)
	if err != nil {
		return nil, err
	}
	secretConfig.Secrets[idx] = config.SecretItem{
		Key:     config.TelemetryAuditLogStreamTLSMaterialsKey,
		RawData: json.RawMessage(jsonData),
	}
```

   `SecretItem` marshals `RawData` under the `data` key and has `Data` tagged `json:"-"` (`secret.go:470-475`), so the rewrite must go through `RawData`. This is exactly what `OAuthClientSecretsUpdateInstruction.cleanup` does (`secret_update_instruction.go:470-492`), including the "remove the whole entry when nothing is left" branch.

7. `yaml.Marshal(secretConfig)` and return `&resource.ResourceFile{Location: location, Data: updatedYAML}`. A non-nil `Data` is an upsert; `cleanupOrphanedResources` uses `Data: nil` for deletion, and both shapes already flow through `AppConfigs.UpdateResources`.

Two boundaries of this behaviour are deliberate:

- **Only a missing stream orphans the material.** An item whose stream still exists but has `tcp.tls.enabled: false` is kept. Toggling TLS off and back on must not silently destroy certificate material the operator would then have to re-upload.
- **Pruning runs only on the portal/API save path.** Editing `authgear.secrets.yaml` on disk in a self-hosted deployment leaves the orphan in place, where it is harmlessly ignored.

### 1.9 Feature config merge — field-level, all the way down

Every level here currently has exactly one field, so a whole-section replace would produce the right answer today. It is still written field-level, per the `update-feature-config` skill: `telemetry` is a namespace that will gain siblings, and the cost of getting this right once is lower than the cost of finding the bug after a sibling is added.

```go
var _ MergeableFeatureConfig = &TelemetryFeatureConfig{}

func (c *TelemetryFeatureConfig) Merge(layer *FeatureConfig) MergeableFeatureConfig {
	return c.merge(layer.Telemetry)
}

func (c *TelemetryFeatureConfig) merge(layer *TelemetryFeatureConfig) *TelemetryFeatureConfig {
	if c == nil && layer == nil {
		return nil
	}
	if c == nil {
		return layer
	}
	if layer == nil {
		return c
	}
	c.AuditLogs = c.AuditLogs.merge(layer.AuditLogs)
	return c
}

func (c *TelemetryAuditLogsFeatureConfig) merge(layer *TelemetryAuditLogsFeatureConfig) *TelemetryAuditLogsFeatureConfig {
	if c == nil && layer == nil {
		return nil
	}
	if c == nil {
		return layer
	}
	if layer == nil {
		return c
	}
	c.Streaming = c.Streaming.merge(layer.Streaming)
	return c
}

func (c *TelemetryAuditLogsStreamingFeatureConfig) merge(layer *TelemetryAuditLogsStreamingFeatureConfig) *TelemetryAuditLogsStreamingFeatureConfig {
	if c == nil && layer == nil {
		return nil
	}
	if c == nil {
```

## 2. Compatibility and deployment behaviour

- **New config only.** `telemetry` is absent from every existing `authgear.yaml`; `SetFieldDefaults` materialises it as an empty section with no streams. No existing document changes meaning.
- **No BREAKING-CHANGES entry.** Nothing that works today stops working: no removed or renamed field, no changed default, and no new refusal of previously accepted input — the only new cross-config rule tolerates rather than rejects.
- **No storage, no migration.** No Redis keys, no SQL, no persisted state.
- **Rollout.** Old binaries reject `telemetry` as an unknown property, because every config schema object in this package sets `additionalProperties: false`. A project must therefore not be given a `telemetry` section until every process serving it runs a binary containing this part. This is the same constraint as every previous new config section and needs no special handling beyond ordinary deploy-then-configure ordering.

## 4. Test plan

`pkg/lib/config` uses Convey (`. "github.com/smartystreets/goconvey/convey"`); every new test matches that style, per the `add-go-test` skill.

### 4.1 `pkg/lib/config/telemetry_test.go` (new)

Table-driven over YAML inputs, asserting on `config.Parse` results and errors:

- minimal valid stream (`name`, `type`, `transport`, `tcp.address`, `syslog.format`, `syslog.framing`) defaults `facility` to `local0`, `app_name` to `authgear`, `structured_data_id` to `authgear`, and `tcp.tls.enabled` to `false`.
- explicit `facility`, `app_name`, `structured_data_id` survive defaulting.
- `type: syslog` without a `syslog` block is rejected.
- `transport: tcp` without a `tcp` block is rejected.
- `name` rejects the empty string, 64 characters, and a `.`; accepts 63 characters, `-` and `_`.
- `facility` rejects an unknown value (e.g. `local8`) and the old numeric form (e.g. `16`, now a type+enum mismatch); accepts `user` and each of `local0`-`local7`.
- `framing` rejects an unknown value; accepts both `octet_counting` and `newline`.
- `app_name` rejects 49 characters and a value containing a space.
- `structured_data_id` rejects `=`, `]`, `"` and a space; **accepts `^`** — this case is what fails if the backslash in the pattern is under-escaped.
- `tcp.address` rejects `collector.internal` (no port), `:5140` (no host), `collector.internal:0`, `collector.internal:70000`; accepts `collector.internal:5140`, `127.0.0.1:5140` and `[::1]:5140`.
- two streams with the same `name` are rejected with the duplicate message; two streams with different names are accepted.

### 4.2 `pkg/lib/config/secret_telemetry_test.go` (new)

- a valid item with only `client_certificate` parses; with only `certificate_authority` parses; with both parses.
- an item with neither is rejected (`anyOf`).
- `client_certificate` with `certificate` but no `key` is rejected, and vice versa.
- `Resolve` returns the matching item and `false` for an unknown name, including on a nil receiver.

### 4.3 Orphan tolerance and pruning

Tolerance, in `pkg/lib/config/secret_test.go` (extend) — these assert the **absence** of an error, and exist so that a future well-meant cross-validation does not reintroduce the boot hazard:

- `SecretConfig.Validate` succeeds for an item whose `stream_name` matches no stream.
- It succeeds for an item whose stream exists but has `tcp.tls.enabled: false`.

Pruning, in `pkg/portal/appresource/manager_test.go` (extend), through `ApplyUpdates0`:

- an `authgear.yaml` update that removes a stream prunes that stream's TLS item and leaves every other secret key byte-identical.
- an item whose stream still exists is kept, including when that stream sets `tcp.tls.enabled: false`.
- removing the last stream removes the whole `telemetry.audit_logs.streams.tls` entry from `secrets`, rather than leaving an empty list.
- an update set **without** an `authgear.yaml` change prunes nothing, even when an orphan exists — this is the `cleanupOrphanedResources` precondition and the reason Deno hooks can be saved before the config that references them.
- an `authgear.yaml` update with no orphans returns no secrets file, so `authgear.secrets.yaml` is not rewritten on every save.

### 4.4 Feature config merge — `pkg/lib/config/testdata/merge_feature.yaml`

Per the `update-feature-config` skill, the case must prove a sibling is not lost. `telemetry` has no sibling of `audit_logs` yet, so the case is written against the nearest real sibling pair — a layer that sets `audit_log.retrieval_days` and a later layer that sets `telemetry.audit_logs.streaming.disabled`, asserting the result carries **both**:

```yaml
- layers:
  - audit_log:
      retrieval_days: 180
  - telemetry:
      audit_logs:
        streaming:
          disabled: true
  result:
    audit_log:
      retrieval_days: 180
    telemetry:
      audit_logs:
        streaming:
          disabled: true
```

`180` and `true` are both non-default, so a whole-section regression cannot produce the expected result by accident.

Add a second case in the reverse layer order, asserting a later layer that omits `telemetry` does not reset `disabled` back to `false`.

### 4.5 Save-time gate — `pkg/lib/config/configsource/resources_test.go` (extend)

Through `AuthgearYAMLDescriptor.UpdateResource`, matching the existing tests in that file:

- `disabled: true`, incoming config with one stream, original with none → rejected with "audit log streaming is disallowed".
- `disabled: true`, incoming **and** original both carry the same stream → accepted (the downgrade subtraction path).
- `disabled: false`, incoming with one stream → accepted.

## 5. Fixed behavioural decisions

These are settled; they are not open questions for the implementer.

1. Config keys are `telemetry.audit_logs.streams` (app), `telemetry.audit_logs.streams.tls` (secret) and `telemetry.audit_logs.streaming.disabled` (feature).
2. `audit_log.retrieval_days` stays a separate top-level feature section and is not moved or aliased.
3. There is **no** cross-validation between the TLS secret and the streams, in either direction. An orphaned item is ignored at load and pruned when `authgear.yaml` is next saved, following `oauth.client_secrets` rather than the LDAP/SAML checks.
4. Only a missing stream orphans the material. An item whose stream exists with `tcp.tls.enabled: false` is kept, so toggling TLS does not destroy certificates.
5. TLS without a secret item is valid and verifies the collector against the system trust store.
6. Pruning happens only on the portal/API save path. A hand-edited `authgear.secrets.yaml` keeps its orphan, harmlessly.
7. Stream name uniqueness is validated in `AppConfig.Validate`, not in the schema.
8. `tcp.address` is not checked against private or link-local ranges.
9. The `type` × `transport` matrix is encoded as an `allOf` clause even though the single-value enums already imply it.
10. Feature config merge is field-level at all three levels despite each having one field today.
