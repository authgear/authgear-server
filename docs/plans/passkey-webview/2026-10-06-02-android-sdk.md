# Passkey in a WebView — part 2: Android SDK

Spec: [docs/specs/passkey-webview.md](../../specs/passkey-webview.md#sdk). Repository: `authgear-sdk-android`.

Parts: [1 server](./2026-10-06-01-server.md) · **2 Android SDK**

## 1. Goal and scope

`WebKitWebViewUIImplementation` enables WebAuthn in its WebView for the app's associated domains, when the device's WebView supports it. Nothing else changes in the SDK. The iOS SDK needs no change: `WKWebViewUIImplementation` works once the app declares `webcredentials:` in its entitlement.

## 2. Dependency — `sdk/build.gradle.kts`

```kotlin
implementation("androidx.webkit:webkit:1.12.1")
```

`1.12.1` is the first release that contains `WebSettingsCompat.setWebAuthenticationSupport`. `1.12.0` shipped without it because of a release bug. This is a new dependency, so it is downloaded on the first build after this change.

## 3. Runtime — `sdk/src/main/java/com/oursky/authgear/WebKitWebViewActivity.kt`

In `onCreate`, after `webSettings.javaScriptEnabled = true`:

```kotlin
if (WebViewFeature.isFeatureSupported(WebViewFeature.WEB_AUTHENTICATION)) {
    WebSettingsCompat.setWebAuthenticationSupport(
        webSettings,
        WebSettingsCompat.WEB_AUTHENTICATION_SUPPORT_FOR_APP
    )
}
```

Imports: `androidx.webkit.WebSettingsCompat` and `androidx.webkit.WebViewFeature`.

`WEB_AUTHENTICATION_SUPPORT_FOR_APP` lets a page use WebAuthn only for a Relying Party ID whose `assetlinks.json` lists the app. When the feature is unsupported, the WebView behaves as today.

## 4. Compatibility

- **Public API:** no change.
- **Apps on an older SDK** keep today's behaviour: the passkey button shows and fails in the WebView.
- **Without the app in any client's `x_native_apps`,** the setting has no effect. The device refuses passkey sign-in because the app is not listed.

## 5. Test plan

No unit test: the change is a WebView setting inside an Activity, and the SDK has no instrumented WebView tests.

Manual, on a physical device, with part 1 deployed and the example app (`javasample`, `app1` debug) listed in the `x_native_apps` of the client it signs in with, with its debug certificate:

1. With **Use WebKit WebView** on, sign in with a password and create a passkey.
2. Sign out, then sign in with the passkey. The request reaches the server, and the server accepts `android:apk-key-hash:`.
3. With the app removed from `x_native_apps`, passkey sign-in is rejected by the server, because the app's `android:apk-key-hash:` origin is no longer accepted. On a device that has not validated the app before, it fails earlier, with `[50152] RP ID cannot be validated`, because `assetlinks.json` no longer lists the app.

These steps repeat the POC recorded in `notes/android-webview-passkey.md` in the SDK workspace, against the real implementation.
