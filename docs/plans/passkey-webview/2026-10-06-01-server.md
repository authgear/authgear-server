# Passkey in a WebView — part 1: server

Spec: [docs/specs/passkey-webview.md](../../specs/passkey-webview.md). Origin rule: [docs/specs/webauthn.md](../../specs/webauthn.md#where-a-ceremony-may-run).

Parts: **1 server** · [2 Android SDK](./2026-10-06-02-android-sdk.md)

## 1. Goal and scope

- Add `x_native_apps` to `oauth.clients[]`.
- Serve `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json`, merged from every client's `x_native_apps`.
- Accept `android:apk-key-hash:<hash>` origins for every listed Android certificate. When a ceremony reports `androidPackageName`, it must be listed with that certificate.

Unchanged:
- The Relying Party ID. `passkey.ConfigService.MakeConfig` keeps deriving it from the request host.
- Clients from Dynamic Client Registration or Client ID Metadata Documents. They are not in `authgear.yaml`, and DCR's default client config has its own type (`OAuthDynamicClientTokenLifetimesConfig`), so they never carry `x_native_apps`.

## 2. Config model and schema

### 2.1 Project config — `pkg/lib/config/oauth.go`

Add to `OAuthClientConfig`, after `CustomUIURI`:

```go
NativeApps []*OAuthClientNativeAppConfig `json:"x_native_apps,omitempty"`
```

Add `"x_native_apps": { "type": "array", "items": { "$ref": "#/$defs/OAuthClientNativeAppConfig" } }` to the `OAuthClientConfig` schema properties. The schema has `additionalProperties: false`, so without this the field is rejected.

New types, in the same file:

```go
type OAuthClientNativeAppPlatform string

const (
	OAuthClientNativeAppPlatformIOS     OAuthClientNativeAppPlatform = "ios"
	OAuthClientNativeAppPlatformAndroid OAuthClientNativeAppPlatform = "android"
)

type OAuthClientNativeAppConfig struct {
	Platform               OAuthClientNativeAppPlatform `json:"platform"`
	TeamID                 string                       `json:"team_id,omitempty"`
	BundleID               string                       `json:"bundle_id,omitempty"`
	PackageName            string                       `json:"package_name,omitempty"`
	SHA256CertFingerprints []string                     `json:"sha256_cert_fingerprints,omitempty"`
}
```

Schema `OAuthClientNativeAppConfig`:

- `additionalProperties: false`, `required: ["platform"]`, and `platform` is an `enum` of `ios`, `android`.
- `team_id`: `"pattern": "^[A-Z0-9]{10}$"`.
- `bundle_id` and `package_name`: `"minLength": 1`.
- `sha256_cert_fingerprints`: `"minItems": 1`, with items matching `"pattern": "^([0-9A-Fa-f]{2}:){31}[0-9A-Fa-f]{2}$"`.
- `allOf`, in the style of the existing `allOf`/`if`/`then` blocks on `OAuthClientConfig`:
  - if `platform` is `ios`: `required: ["team_id", "bundle_id"]`, and `not` any of `package_name` or `sha256_cert_fingerprints`;
  - if `platform` is `android`: `required: ["package_name", "sha256_cert_fingerprints"]`, and `not` any of `team_id` or `bundle_id`.

`x_native_apps` is accepted on every client type; the spec sets no client-type rule.

### 2.2 Cross-client validation — `pkg/lib/config/config.go`

JSON Schema cannot express uniqueness across clients. Add a step to `AppConfig.Validate`, after Validation 12:

```go
// Validation 13: an app is listed in x_native_apps at most once across all clients.
c.validateOAuthClientNativeApps(validationCtx)
```

```go
func (c *AppConfig) validateOAuthClientNativeApps(ctx *validation.Context)
```

It loops once over `c.OAuth.Clients`, and within each client over `NativeApps`. It keeps two sets: `bundle_id` for `ios` entries and `package_name` for `android` entries. A repeated value emits an error at `/oauth/clients/<i>/x_native_apps/<j>/bundle_id` or `/oauth/clients/<i>/x_native_apps/<j>/package_name`, through `ctx.Child("oauth", "clients", strconv.Itoa(i), "x_native_apps", strconv.Itoa(j), ...)`, the same way `validateTokenLifetime` builds its path. Capture the exact error text from a throwaway `config.Parse` test, as the `update-configs` skill requires.

### 2.3 Portal

No change. The portal reads clients from the raw config. `getReducedClientConfig` (`portal/src/graphql/portal/EditOAuthClientForm.tsx:68`) spreads the remaining fields, and `updateClientConfig` changes one field with `produce`, so saving a client in the portal keeps `x_native_apps`.

## 3. Runtime flow

### 3.1 Shared helpers — `pkg/lib/feature/passkey/native_apps.go` (new)

```go
// EffectiveNativeApps returns every client's x_native_apps in config order
// (client order, then entry order).
func EffectiveNativeApps(oauth *config.OAuthConfig) []*config.OAuthClientNativeAppConfig

// AndroidOrigin converts a colon-separated SHA-256 fingerprint to
// "android:apk-key-hash:" + base64.RawURLEncoding(bytes).
func AndroidOrigin(sha256CertFingerprint string) (string, error)
```

`EffectiveNativeApps` does not consult `authentication.identities`. A custom authentication flow can offer passkeys without it, so the listed apps take effect whenever they are listed.

`AndroidOrigin` removes `:`, decodes with `hex.DecodeString`, which accepts both cases, and returns an error unless the result is 32 bytes. The schema pattern already guarantees 32 bytes.

### 3.2 Accepted origins — `pkg/lib/feature/passkey/config_service.go`, `config.go`

`ConfigService` already has `OAuthConfig` (from the Custom UI fix), which is all it needs, so its fields and wiring are unchanged.

Add to `Config` in `config.go`:

```go
// AndroidPackageNames maps each android:apk-key-hash origin in RPOrigins to
// the package names listed with that certificate.
AndroidPackageNames map[string][]string
```

Call flow, once per `MakeConfig`:

1. `MakeConfig` calls `s.makeRPOrigins(origin)`, which now returns `(origins []string, androidPackageNames map[string][]string)`.
2. `makeRPOrigins` builds the public origin and the Custom UI origins as today, then calls `s.appendAndroidOrigins(origins, seen, androidPackageNames)`.
3. `appendAndroidOrigins` loops over `EffectiveNativeApps(s.OAuthConfig)`, keeps `android` entries, and calls `AndroidOrigin` for each fingerprint.
   - A conversion error is skipped, as `makeRPOrigins` already skips an unparseable `x_custom_ui_uri`.
   - New origins are de-duplicated through `seen` and appended.
   - Each entry's `PackageName` is appended to `androidPackageNames[origin]`.
4. `MakeConfig` stores both results in `Config.RPOrigins` and `Config.AndroidPackageNames`.

```go
func (s *ConfigService) appendAndroidOrigins(origins []string, seen map[string]struct{}, androidPackageNames map[string][]string) []string
```

### 3.3 Android package name — `pkg/lib/feature/passkey/service.go`

The `android:apk-key-hash:` origin identifies only the certificate, so every app signed with it maps to the same origin. go-webauthn v0.15.0's `CollectedClientData` has no `androidPackageName`, so the raw `clientDataJSON` is decoded.

```go
// checkAndroidPackageName returns nil unless origin is an android:apk-key-hash
// origin and clientDataJSON reports a package name not listed with it.
func checkAndroidPackageName(config *Config, origin string, clientDataJSON []byte) error
```

1. If `origin` has no `android:apk-key-hash:` prefix, return `nil`.
2. Decode `clientDataJSON` into a local struct with one field, `AndroidPackageName string`, tagged `json:"androidPackageName"`. A decode error returns `protocol.ErrVerification.WithDetails("invalid clientDataJSON")`.
3. If `AndroidPackageName` is empty, return `nil`. The origin check has already passed. The spec requires a match only when the package name is reported.
4. If it is not in `config.AndroidPackageNames[origin]`, return `protocol.ErrVerification.WithDetails("androidPackageName is not listed for this origin")`.

Call sites, each once, right after `Verify` returns `nil`:

- `PeekAttestationResponse`: `checkAndroidPackageName(config, parsed.Response.CollectedClientData.Origin, parsed.Raw.AttestationResponse.ClientDataJSON)`.
- `PeekAssertionResponse`: `checkAndroidPackageName(config, parsedAssertion.Response.CollectedClientData.Origin, parsedAssertion.Raw.AssertionResponse.ClientDataJSON)`.

A non-nil error is returned the same way a `Verify` error is, so callers treat it as a failed ceremony.

### 3.4 Association files — `pkg/auth/handler/wellknown` (new package)

The association files are not OAuth metadata, so they get their own package instead of `pkg/auth/handler/oauth`.

`association_files.go`:

```go
func ConfigureAppleAppSiteAssociationRoute(route httproute.Route) httproute.Route // GET /.well-known/apple-app-site-association
func ConfigureAssetLinksRoute(route httproute.Route) httproute.Route              // GET /.well-known/assetlinks.json

type AppleAppSiteAssociationHandler struct {
	OAuthConfig *config.OAuthConfig
}

type AssetLinksHandler struct {
	OAuthConfig *config.OAuthConfig
}
```

Wiring:
- `deps.go`: `var DependencySet = wire.NewSet(wire.Struct(new(AppleAppSiteAssociationHandler), "*"), wire.Struct(new(AssetLinksHandler), "*"))`.
- `pkg/auth/deps.go`: add `handlerwellknown.DependencySet` next to `handleroauth.DependencySet`.
- `pkg/auth/wire_handler.go`: `newAppleAppSiteAssociationHandler` and `newAssetLinksHandler`, in the same shape as `newOAuthMetadataHandler`.
- `pkg/auth/routes.go`: register both on `oauthStaticRoute`, next to the OIDC metadata routes:

```go
router.Add(handlerwellknown.ConfigureAppleAppSiteAssociationRoute(oauthStaticRoute), p.Handler(newAppleAppSiteAssociationHandler))
router.Add(handlerwellknown.ConfigureAssetLinksRoute(oauthStaticRoute), p.Handler(newAssetLinksHandler))
```

`oauthStaticChain` applies `CORSStar` and `PublicOriginMiddleware`. So the files are served only at the public origin's host, with no authentication.

`AppleAppSiteAssociationHandler.ServeHTTP`:

1. `apps := passkey.EffectiveNativeApps(h.OAuthConfig)`, keeping `ios` entries.
2. If there are none, `http.NotFound`.
3. Otherwise `Content-Type: application/json`, `200`, and the body `{"webcredentials":{"apps":["<team_id>.<bundle_id>", ...]}}`, in config order.

`AssetLinksHandler.ServeHTTP`:

1. `apps := passkey.EffectiveNativeApps(...)`, keeping `android` entries.
2. If there are none, `http.NotFound`.
3. Otherwise `Content-Type: application/json`, `200`, and one statement per entry, in config order:

```json
{
  "relation": [
    "delegate_permission/common.handle_all_urls",
    "delegate_permission/common.get_login_creds"
  ],
  "target": {
    "namespace": "android_app",
    "package_name": "<package_name>",
    "sha256_cert_fingerprints": ["<fingerprint, upper-cased>"]
  }
}
```

Fingerprints are upper-cased in the output, because the spec compares them case-insensitively and Android tooling prints them in upper case. No `Cache-Control` header is added.

## 4. Compatibility and deployment

- **Additive only.** A project without `x_native_apps` sees no change to its origin list or responses. Both new paths return `404`, as they do today.
- **No feature flag.** `x_native_apps` takes effect whenever apps are listed.
- **No storage or migration.**
- **`robots.txt`** is unchanged. A POC confirmed that its default `Disallow: /` does not block verification of `assetlinks.json`.

**`native_apps_test.go`:**
- `EffectiveNativeApps`: every client's entries, in client order then entry order; nil-safe.

  - accepts lower case;
  - rejects a wrong length.

The existing `service_test.go` cases verify fixed, pre-signed responses, so a unit test cannot sign a fresh ceremony from an `android:apk-key-hash:` origin. Unit tests in `native_apps_test.go` therefore cover what decides the outcome, and the e2e tests cover full sign-ins:
- `makeRPOrigins`: the origin of each listed Android certificate is accepted, with its package names recorded across clients; iOS entries add no origin.
- `checkAndroidPackageName`: a web origin is ignored; a listed `androidPackageName` is accepted; an unlisted one is rejected; a ceremony without it is accepted; invalid `clientDataJSON` is rejected.

**`association_files_test.go`:** `httptest` against both handlers. Assert:
- `404` with no entries;
- `200`, `application/json`, and the exact body for one and two entries per platform, across two clients;
- upper-cased fingerprints.

**e2e (`e2e/tests/passkey/`):** YAML, per the `write-e2e-test` skill. A test file has one configuration, so each configuration gets its own file. The override restates the `e2e` client, as `passkey_custom_ui_origin.test.yaml` does, because arrays in the override replace the base config's.

  - sign in with `generatePasskeyAssertion` and the origin `android:apk-key-hash:<hash of the listed fingerprint>` → `finished`;
  - sign in with an unlisted hash → the error.

Run each new test until it passes, as the skill requires.

## 7. Fixed behavioural decisions

- **No client-type rule.** `x_native_apps` is accepted on any client in `authgear.yaml`.
- **When it takes effect.** `x_native_apps` applies whenever apps are listed. It does not depend on `authentication.identities`, because a custom authentication flow can offer passkeys without it.
- **Missing files.** A path with no entries for its platform returns `404`.
- **Missing package name.** A ceremony without `androidPackageName` is accepted once its origin is.
- **Handler location.** The association handlers live in the new package `pkg/auth/handler/wellknown`.
- **Output order and case.** Fingerprints are upper-cased in output. Entries keep config order: client order, then entry order.
