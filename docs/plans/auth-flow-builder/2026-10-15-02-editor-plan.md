# Auth flow editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the read-only auth flow viewer into an editor that changes a flow in a draft and saves it to the project config.

**Architecture:** The draft is the flow's own config object. Every edit is a pure function in `portal/src/graphql/portal/authflows/edit/` that returns a new flow and the pointer to select. The viewer pipeline (`flowToTree` → `treeToGraph` → `layoutGraph`) re-runs on each change; the canvas keeps node sizes across changes instead of remounting. Saving goes through `useAppConfigForm`, replacing one flow in the raw config.

**Tech Stack:** React 18, @xyflow/react 12, Radix Themes, immer, js-yaml, Monaco (`CodeEditor`), Jest (ts-jest, `@jest/globals`).

**Spec:** `docs/plans/auth-flow-builder/2026-10-15-01-editor-design.md`

## Global Constraints

- Everything stays behind `portal.auth_flow_builder_enabled`.
- Every user-facing string goes through `en.json`, with literal message IDs (lookup tables, no concatenation).
- Never drop an error silently.
- No commits unless fung asks.
- An edit never leaves the draft invalid for the schema; it is blocked instead.
- A control writes only the field it owns; unknown fields survive.

## Review Focus

- A flow loaded from hand-written YAML with fields the portal does not know: saved unchanged, the config is equal to the input.
- Inserting on the line after a single-option step (drawn inline): the step lands in that option's `steps` when it has any, otherwise after the step.
- Removing a step whose nested steps are targeted, where the referencing step is outside the removed subtree: blocked.
- An `updateApp` validation error inside the edited flow when the flow was appended (generated → custom): the pointer index is the appended position.
- Editing quickly: the canvas keeps its viewport, and a newly inserted node is not drawn at (0,0) before it is measured.

### Task 1: Edit rules (what each flow type allows, and new-step defaults)

**Files:**
- Create: `portal/src/graphql/portal/authflows/edit/rules.ts`
- Test: `portal/src/graphql/portal/authflows/edit/rules.test.ts`

**Interfaces:**
- Produces:
  - `allowedStepTypes(flowType: FlowType): string[]` (spec table, config order)
  - `allowedIdentifications(flowType): string[]`, `allowedAuthentications(flowType, stepType: "authenticate" | "create_authenticator"): string[]` (schema enum order)
  - `newStep(flowType, type, targetStep: string | null): AuthenticationFlowStepConfig` (spec "Starts with" table)
  - `newOption(flowType, step): AuthenticationFlowOptionConfig | null` (first unused; null when none left)
  - `CHOICE_STEP_TYPES`, `TARGETING_STEP_TYPES: Record<"verify" | "change_password", string>` (the type each targets)

Tests: each flow type's list; `newStep` for every type, including account recovery identify (nested `select_destination`), signup_login identify (`default` flows), `fill_form` (`/given_name`), `verify` with a target; `newOption` skips used values and returns null when all are used.

### Task 2: Pointers and edit functions

**Files:**
- Create: `edit/pointer.ts`, `edit/edits.ts`; tests beside them.

**Interfaces:**
- `parsePointer(p: string): (string | number)[]`, `getAt(flow, p)`, `parentSteps(p): { steps: string; index: number }` (for `/steps/2/one_of/0/steps/1` → `{steps: "/steps/2/one_of/0/steps", index: 1}`)
- `InsertionPoint = { steps: string; index: number }` (pointer to a steps array, which may not exist yet)
- `EditResult = { flow: AuthenticationFlowConfig; selected: string | null }`
- `insertStep(flow, at: InsertionPoint, step): EditResult` (selected = new step's pointer)
- `removeStep(flow, pointer): EditResult` (selected null)
- `addOption(flow, stepPointer, option): EditResult` (selected = step)
- `removeOption(flow, stepPointer, index): EditResult`
- `updateStep(flow, pointer, recipe: (draft: AuthenticationFlowStepConfig) => void): EditResult` (immer)
- `replaceStep(flow, pointer, step): EditResult`
- `countNestedSteps(step): number`

All immutable (immer `produce`). Tests: insert into a missing option `steps`, at 0 and at end; remove; option add and remove; `updateStep` keeps unknown fields; unchanged reference for untouched siblings.

### Task 3: References

**Files:**
- Create: `edit/references.ts`; test beside it.

**Interfaces:**
- `earlierSteps(flow, pointer): string[]` (ancestors, earlier siblings at each level, and their descendants)
- `targetCandidates(flow, pointer, usage: "verify" | "create_authenticator" | "authenticate" | "change_password"): { pointer: string; name: string | null }[]`
- `referencesTo(flow, pointer): string[]` (pointers of steps or options whose `target_step` resolves to the step's name)
- `removalBlockers(flow, pointer): string[]` (references into the subtree from outside it)
- `renameStep(flow, pointer, name): EditResult & { rewritten: boolean }` (rewrite only when the old name is unique)
- `ensureNamed(flow, pointer, base: string): { flow; name }` (unique name like `identify`, `identify_2`)
- `ReferenceWarning = "missing" | "wrong_type" | "not_earlier"`, `referenceWarnings(flowType, flow): Map<string, ReferenceWarning>` keyed by the pointer of the step holding the reference (option references key on the step)
- `duplicateNames(flow): Set<string>`

Tests: generated signup and login fixtures have no warnings; removal blocked when a nested step is targeted from outside, allowed when the referencer is inside; rename with and without duplicates; candidates exclude unnamed, wrong-type and later steps and id_token-only identify for authenticate.

### Task 4: Insertion points on graph edges

**Files:**
- Modify: `graph.ts`, `graph.test.ts`

**Interfaces:**
- `FlowGraphEdge.insertAt: InsertionPoint | null`

Rule: the outlet of item X carries the point after X: for X drawn inline with one option j (`branches == null` and a non-device option), `{X/one_of/j/steps, 0}` when that option has steps, else after X in its parent. An option outlet carries `{X/one_of/j/steps, 0}`. Start carries `{/steps, 0}`. Hand-off edges carry null. Tests per line kind of the spec table, and the inline case both ways.

### Task 5: Save model and error mapping

**Files:**
- Modify: `portal/src/hook/useAppConfigForm.ts` (expose `rawConfig`)
- Create: `edit/save.ts`; test beside it.

**Interfaces:**
- `EditorState = { draft: { type: FlowType; name: string; flow: AuthenticationFlowConfig } | null }`
- `rawFlow(raw, type, name): AuthenticationFlowConfig | null`
- `replaceFlow(raw, type, name, flow): PortalAPIAppConfig` (replace or append; other keys untouched)
- `flowPointer(raw, type, name): string` (`/authentication_flow/<type>_flows/<index>`, index of the match or the append position)
- `stepErrors(error: unknown, flowPointer, nodeIDs: string[]): Map<string, string[]>` (longest-prefix node; messages from `ValidationFailed` causes)

Tests: round trip with an unknown field; replace vs append; pointer for append; error mapping to the deepest node and to none.

### Task 6: Canvas that updates in place

**Files:**
- Modify: `FlowCanvas.tsx`, `nodeChanges.ts` (+ test), `AuthFlowsScreen.tsx` (canvas key = flow key only)

Keep measured sizes in a `Map` state fed by dimension changes; derive nodes from the graph each render; compute layout from known sizes; keep the last complete layout's positions while new nodes are unmeasured, and hide unmeasured nodes. `fitView` only on first layout. Test: `splitNodeChanges` returns sizes.

### Task 7: Edit mode on the canvas

**Files:**
- Modify: `FlowSketchContext.tsx`, `FlowEdges.tsx`, `FlowNodes.tsx`, `sketches.tsx`, CSS modules
- Create: `edit/StepPicker.tsx`

Context gains `editor: { onInsert(at, type); onAddOption(stepPointer); onRemove(pointer); errors; warnings; pickerDisabled(at, type) } | null`. Edges with `insertAt` render a hover/focus "+" (`EdgeLabelRenderer`) opening the picker. Choice cards render "+ Add option" in edit mode. The selected node gets an xyflow `NodeToolbar` with Remove (confirmation when nested steps exist; disabled with the reason when blocked). Nodes with errors get a red outline, with warnings a warning line.

### Task 8: Screen: edit, discard, save

**Files:**
- Modify: `AuthFlowsScreen.tsx`, `query/authFlowsScreenQuery.graphql` (+ regenerated `.ts`)

Wire `useAppConfigForm<EditorState>` (state null draft = viewing), `FormContainerBase` for the navigation blocker, conflict dialog and error context. Edit (generated → confirmation dialog), Discard, Save; pickers disabled while dirty; selection follows `EditResult.selected`.
